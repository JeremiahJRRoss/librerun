## [1.1.0-beta.1] — 2026-10-01

### Highlights

The first public release of LibreRun, a beta: built for educational
purposes, released as source only, under AGPL-3.0-only. The announcement,
`docs/release/v1.1.0-beta.1.md`, says what LibreRun is for, what the beta
adds to the certified and never published 1.0, what it does not do yet,
what a beta means for an upgrade, and how this candidate was certified;
`docs/platform/Install.md` §10 is the upgrade from 1.0.

- **Source only, under the AGPL.** Nothing is published but the tree and
  its source archives: no image, wheel or package. Every first-party image
  is built from the checkout and never pulled, and a running LibreRun says
  which licence it is under and where the source of its version is.
- **HTTPS at the edge, with certificates the admin manages.** An opt-in
  edge terminates TLS on one port while the plain ports stay on loopback;
  Admin → Application Settings → Certificates says what it serves and what
  it needs, and loads a CA with no shell or restart.
- **Settings and secrets as data.** An agent's settings are per tenant; a
  secret setting, a tool secret and a provider key are set in the admin UI
  and stored encrypted, a provider key sealed in the browser to the
  gateway, so the backend never holds it in the clear.
- **The admin surface, complete:** the Deployment panel, the Keys tab, and
  every platform page explained to a tenant admin.
- **Dependencies pinned by identity:** every image by tag and digest, the
  gateway on a hashed lock, Valkey 8 as the cache server.

Everything below is the beta, batch by batch, each under its own heading.

- **K5a — agent settings as data: the platform surface** (2026-09-27; L32,
  D17). An agent declares the settings it reads in its manifest —
  `settings[]`, each a key, a type (`string`, `int`, `float`, `bool`,
  `enum`, `string_list`) and a default — and gets a Settings tab on its
  admin page, a container included, where each tenant's admin edits the
  values that tenant's runs read. The values live per tenant in the new
  `agent_settings` table (migration `0018_agent_settings`), a row only
  where a value differs from the default, and each is held to its type
  strictly: a boolean is never an integer. A run reads them when it asks,
  through the façade's new `config` member (`caps.config.settings()`,
  `caps.config.steps()`) or, in a container, `ctx.config.settings()`, the
  MCP `config_get` tool, which answers `{steps, settings}`. `has_config`
  now means the page has a Steps or a Settings tab. The echo example
  declares a `note` setting and reads it back under `show_settings`.
  **Gate T** (`backend/tests/test_gate_t.py`) holds one agent's settings
  for two tenants apart in the admin API, the façade and `config_get`,
  with a double that drops the tenant predicate in every run; and
  `backend/tests/test_alembic_single_head.py` fails a migration graph with
  more than one head, the fork two migration batches in one wave can leave.
- **K6 — the encrypted secrets store and the `secret` setting type**
  (2026-09-28; L30, L31, D14, D32, D33). A platform admin sets the
  Microsoft sign-in secret in Admin → Settings, and the next sign-in uses
  it with nothing restarted. The value lives in the new `secrets` table
  (migration `0019_secrets`) as MultiFernet ciphertext under
  `LIBRERUN_BACKEND_SECRETS_KEY` — a comma-separated list of Fernet keys,
  the first current, `_FILE`-capable, handed to the backend alone — and
  appears in no response, log line, trace, audit detail or Redis: the page
  shows where the value comes from (`runtime`, `env`, `unset`, or
  `unreadable` for a row sealed under a key no longer configured) and a
  keyed fingerprint, and the input is never pre-filled. A blank key means
  "unconfigured" in every mode: setting a secret answers `503
  secrets_store_unconfigured` and each secret setting falls back to its
  environment variable, so a deployment that sets no key loses nothing; a
  malformed key stops the backend at boot, naming the entry's position.
  `python -m app.scripts.rewrap_secrets [--dry-run]` re-encrypts the
  backend's rows under the current key after a rotation, and names the rows
  no key opens. The Google and Microsoft sign-in ids are runtime settings
  too (`auth.google_client_id`, `auth.azure_client_id`,
  `auth.azure_tenant_id`), read per sign-in. `scripts/demo.sh` and
  `librerun demo` generate the key in Fernet's format and top up a demo
  `.env` that predates it; `librerun doctor` says whether it is set, blank
  or malformed, and, signed in as a platform admin, which secret settings
  have a row under a key no longer configured. **Gate S** reads sixteen
  sinks: a secret set through the settings API and the store's key are
  slots, the `secrets` table a sink whose planted fingerprint the sweep
  must find, each slot with a negative double of its own.
- **T1 — edge TLS** (2026-09-28; L35, D37). HTTPS between the browser and
  LibreRun, opt-in: `./compose.sh --profile app --profile tls up -d
  --build` runs the `edge` service — Caddy 2.11.4, pinned by digest,
  configured by `config/Caddyfile` — which terminates TLS on one published
  port (`LIBRERUN_HTTPS_PORT`, 8443) and hands `/api/v1/*` to the backend
  and everything else to the web UI. The certificate comes from Caddy's
  local CA (`LIBRERUN_TLS=internal`, the default), from ACME (an e-mail), or
  from your own files (`/certs/<cert> /certs/<key>`, mounted from
  `LIBRERUN_TLS_CERT_DIR`), for the name in `LIBRERUN_TLS_DOMAIN`. It sends
  HSTS (for any name but `localhost`), `nosniff`, `X-Frame-Options: DENY`,
  a referrer policy and a baseline CSP. `compose.sh` refuses the profile —
  exit 4, before anything starts, naming each line to set — unless
  `BACKEND_PORT` and `FRONTEND_PORT` are on loopback, `NEXT_PUBLIC_API_URL`
  is `/api/v1` and `BACKEND_INTERNAL_URL` is `http://backend:8000`, because
  Docker's publishing bypasses ufw and firewalld and no override can remove
  a publish. The backend believes forwarding headers from the edge's fixed
  address alone, so audit and session rows record the browser's address.
  That address sits on the `edge` network, which every start creates, so
  its first three octets are one line, `LIBRERUN_EDGE_NET` (default
  `172.16.87`): a second LibreRun on one host, or a network already on
  `172.16.87.0/28`, moves it, since an engine refuses a subnet another
  network holds.
  `librerun doctor` and `librerun run` take `--cacert` (or
  `LIBRERUN_CA_FILE`) and reach `LIBRERUN_URL` when it is set, and an
  https base is the edge's origin, run page included; given no
  `--base-url`, doctor signs in only through this checkout's own edge, at
  the address the engine vouches for, under the host name the certificate
  carries. `scripts/librerun_smoke.py` takes `--cacert`. **The TLS gate**,
  `librerun-smoke` → `tls-edge`, proves it on a stack reached as
  `librerun.test`. The keyless demo stays plain HTTP on `localhost`.
  `docs/platform/Install.md`, "HTTPS at the edge".

- **K7 — provider keys from the UI, sealed to the gateway** (2026-09-29;
  L33, D15, D16, D19, D33, D34). A platform admin pastes a provider key in
  **Admin → Application Settings → Model providers**; the browser seals it
  to the gateway's public key (RSA-OAEP with SHA-256, 3072 bits, a label
  per provider), the backend stores and relays a blob it cannot open — it
  holds no RSA code and no private key — and the gateway opens it, keeps
  it under its own store key and uses it from the next model call, with
  nothing restarted. A key set there wins over `gateway.env`'s for its
  provider, and Clear hands the provider back; `gateway.env` works as
  before. `LIBRERUN_GATEWAY_SECRETS_KEY` (in `gateway.env`, `_FILE`-capable,
  never the backend's key) is the gateway's store key: the demo writes one,
  and `python -m gateway.rewrap` rotates it, replaces the sealing keypair
  (`--rotate-keypair`) or discards what a lost key left behind
  (`--discard-unopenable`). The page shows the fingerprint of the key it
  seals to, which the gateway logs at boot as `gateway_sealing_key`:
  compare them once (D34). Off a secure context it refuses to seal and
  says why (D19). `GET /api/v1/admin/providers`, and `POST` and `DELETE
  /api/v1/admin/providers/{name}/key`, which refuses a raw key `400
  plaintext_refused`; migration `0020_gateway_status`, the row the gateway
  writes to say what it holds. `librerun doctor` reports the store key and
  lists the providers. Gate S sweeps seventeen sinks, a sealed provider key
  among its slots; `librerun-smoke` → `provider-keys` proves a pasted key
  reaches a mock provider with the gateway unrestarted, and `tls-edge`
  walks the page in Chromium through the edge. `docs/platform/Install.md`,
  "The gateway's store key" and "Model providers".
- **K8a — tool secrets: the backend path** (2026-09-29; D20, D32, D35,
  D36; gap D3). An agent names the third-party secrets it reads in its
  manifest's `secrets[]`; a tenant's admin sets this tenant's value and a
  platform admin every tenant's default through `GET /api/v1/agents/{id}/secrets`
  and `PUT` and `DELETE /api/v1/agents/{id}/secrets/{tenant|agent}/{name}`
  — never answering a value, audited without one, and `400
  secret_value_invalid` for a value under 8 or over 4096 characters. A run
  reads its tenant's value through `caps.secrets.get(name)` in-process,
  falling back to the upper-cased name in the backend's environment, or
  through the MCP tool `secret_get` from the store alone; an undeclared
  name is `SecretNotDeclared` (`-32005`), an unset one `SecretNotSet`
  (`-32006`), and neither needs a grant. The runner scrubs every value it
  delivered from what the run persists — output, report, error text,
  progress, audit details, run-store values, and an exception the agent
  raises before it is traced or logged — as `[REDACTED_SECRET]`, a value
  the run was handed included after an admin replaces it, and refuses a
  key or a name holding one (`secret_in_output`). The knowledge
  base's key is the platform secret setting `kb.pinecone_api_key` in Admin
  → Settings, `PINECONE_API_KEY` its fallback. Gate S sweeps eighteen
  sinks, a tool secret set for a tenant among its slots and what a run
  persists among its sinks; Gate T holds tool secrets apart per tenant.
  `docs/platform/Install.md`, "An agent's tool secrets".
- **A2 — source-only distribution** (2026-09-29; L37, D26; R11, R12). A
  release publishes source and nothing else, and two jobs hold it.
  `release-readiness` → `no-publication` runs
  `scripts/check_no_publication.py`, which reads every workflow and local
  action and fails naming the file, line and rule of any capability to
  publish — a registry login, a push or cache export, a package publish,
  a release asset, a permission that could publish or sign (`pages` and
  `id-token` write in `docs-site.yml` alone), a workflow with no top-level
  `permissions:`, a secret but `GITHUB_TOKEN`, a step behind `if: false`
  included, and each however it is spelled: a registry exporter is a push,
  and a quoted key is the key — and `scripts/publication_probes.sh`
  plants each one to prove it is caught. `librerun-smoke` → `source-build` holds compose's resolved
  model to `pull_policy: build` with `scripts/check_pull_policy.py`, then
  starts the stack from an `up` with no `--build`: six images built under
  a loopback listener's prefix, and nothing asked of it.
  `docs/platform/Releasing.md` §3, "What a release is".
- **T2 — certificates the admin sees and manages** (2026-09-30; L42,
  L43, D44). Admin → Application Settings → **Certificates** says what the
  HTTPS edge serves — the site's names, the issuer, the certificate's and
  the root's dates and SHA-256 — where it comes from and why, and what it
  needs next, each need with its action: trust the root (its fingerprint
  and a download), the root changed since it was acknowledged, a
  certificate or a CA ending, ACME's public name and port, restart the
  edge, or the edge off. A platform admin loads a CA — at install, or after
  a restore to keep the root the browsers already trust — brings a
  certificate and key, chooses ACME, or goes back to the environment's
  setting, without a shell or a restart; each choice has its environment
  line, and the new `LIBRERUN_TLS_CA` is the environment's way to load a CA.
  The edge's admin API is a Unix socket on a new control volume that only
  the edge and the new `edge-control` service mount: the backend's image
  with no database, secret or agent, which checks every file before the
  edge sees it, reloads the edge in seconds, and undoes a change the edge
  refuses. The edge sends it a change only after asking the backend
  whether the caller is a platform admin, with the headers and never the
  body, so a key never enters the backend's process; none is ever
  returned, logged or backed up. `docs/platform/Install.md`, "HTTPS at the
  edge".
- **B1a — the release machinery** (2026-09-30; P01, D38; R18). Every
  release after the first is one commit on the public `main`, a
  fast-forward: `scripts/prepare_public_repo.sh --parent <public main>
  --base <previous release's source>` makes it, with the candidate's tree
  and the public identity, and refuses — `--check` included — unless
  `--base` was a release's source and the candidate carries every commit
  made in the public repository since (`git merge-tree --write-tree
  --merge-base`, git 2.40 or later), naming each path it would revert.
  `scripts/resolve_public_owner.sh <handle>` writes the public owner into
  every site in one reviewable edit, `CODEOWNERS` as one user, and refuses
  a handle GitHub would not take or `publish-purity` flags.
  `release-readiness` → `public-commit` runs `scripts/public_commit_probes.sh`:
  in a throwaway clone it resolves a probe owner, prepares a first commit
  and a fast-forward and publishes both to a local bare repository, and
  plants each refusal, which must go red. `docs/platform/Releasing.md` §5
  and §6 are the release owner's procedure for a personal account.
- **K9 — the admin surface, complete** (2026-09-30; L28, L29, L31, D16,
  D29, D30, D43). Admin → Application Settings gains a read-only
  **Deployment** panel: the version, licence and source; the gateway's
  version, report and keyless mode; each posture and bootstrap setting
  with its value, whether it came from the environment or is the default,
  and where to change it; whether each OTLP header variable is set, never
  its value; and the transport the page came over, linked to Certificates
  through the edge. It is an allowlist of names read one by one
  (`GET /api/v1/admin/deployment`): never a secret, the environment or a

  platform admin: issue a first gateway key, rotate it with a grace window
  of 0 to 720 hours, or revoke; a new value is shown once, with Copy, and
  stored nowhere, and a key from the environment says it rotates in
  `.env`. Every editable field carries its scope chip; a tenant admin on a
  platform page is told "Platform operators only." and why; the admin hub
  says what each page edits and lists the ids a key is installed for with
  no agent registered; and `librerun doctor`, signed in as a platform
  admin, prints "Deployment (as the backend reads it)".
  `docs/platform/Install.md`, "The admin surface".
- **A3 — dependency identity and the inventory** (2026-09-30; L37, L38,
  D25, D27; R14, R16). `docs/release/Distribution_Surface_Matrix.md`

### Fixed

- Third-party text in the tree carries its own licence: Alembic's
  scaffold (MIT), the Contributor Covenant (CC BY 4.0) and GitHub's
  gitignore template (CC0).
- The conduct and security contacts are `dev@librerun.dev`, and
  `CODEOWNERS` names a personal account; its handle is still a
  placeholder.
- The SDK's install lines no longer point at a PyPI name the project does
  not publish.
- **A1 — three gaps in the licence checks** (2026-09-26; #148 items 1, 2
  and 5). The purity probes decide whether they run in the development
  repository from the event's `repository.private` — locally, from the
  repository's name against the public one's — and never from the check
  they test, so a deleted digest or length now turns the job red instead
  of skipping it; a probe plants the repository's name alone. `bundle`
  reads what `git archive` itself carries, so an `export-ignore` on a
  directory counts. `statements` catches the two wordings the licence
  reconciliation removed. Each fix has probes that go red.
- **T1 (2026-09-28): `BACKEND_INTERNAL_URL` reached the web UI only at
  run time**, and Next computes its `/api/v1` rewrite at build time, so
  every layout that set it — the reverse-proxy ones in `.env.example` —
  proxied nothing and answered 404. It is now a build argument too;
  rebuild the web UI after changing it.
- **Before wave 2 (2026-09-28): the TLS guard did not know `*`.**
  `--profile '*'` and `COMPOSE_PROFILES=*` enable every profile, the
  edge's among them, and `compose.sh` looked for `tls` by name, so either
  started the edge with the plain ports wherever `.env` put them. Both are
  refused now, exit 4, as `tls` is; and a commented-out
  `${BACKEND_PORT:-…}` line in `compose.yaml` no longer stands for the
  default the guard reads.
- **Before wave 2 (2026-09-28): `librerun up` and `librerun demo`
  returned before the gateway answered**, on the backend's health alone,
  so a run started straight after could meet a gateway still starting.
  Both now wait up to two minutes for `/api/v1/meta` to report the gateway
  up, and name `librerun logs gateway` when it does not.
- **After K7 (2026-09-29): a secret setting was announced before it was
  committed.** Saving or clearing a secret in Admin → Settings bumped
  `secrets:version` inside the request's transaction, so another backend
  process reading in between could keep the old value for up to 30
  seconds. The routes now commit the row and its audit, then tell every
  process, as K7's provider-key routes do.
- **After K7 (2026-09-29): the demo's store key could go into a readable
  `.env`.** `scripts/demo.sh` and `librerun demo` add
  `LIBRERUN_BACKEND_SECRETS_KEY` to a demo `.env` that lacks it, and a

- **The provider keys left `.env` (K1).** Three secrets were delivered by
  the file every process reads, to the one process that reads them, by way
  of `${OPENAI_API_KEY:-}` in the gateway's compose block. They now live

  orders. `repository_root()` handles the image's flattened
  `/app/gateway/` layout, where the old arithmetic would have raised at
  import and taken the container down.
- **Gate P: no process receives a secret it does not read (K1, L28).**
  `backend/tests/test_secret_partition.py` derives what every compose
  service *receives* — from `compose.yaml`, `agents.compose.yaml` and the
  committed example beside every `env_file` a service names, so a key
  delivered by a file counts exactly as much as one interpolated into
  `environment:` — and what every process *reads*, from the two settings
  models, the backend modules the gateway imports and reads `settings.X`
  from, and a narrow registry for the readers that are not Python
  (Postgres, Vector, the OTLP bridge, the frontend build, an agent
  container). `received - read` must be empty for every service. Four
  negative probes, each proven red: a provider key interpolated into the
  backend's `environment:`; the same key handed to the backend by
  `env_file`; a provider key back in `.env.example`; and the violation
  injected into the real `compose.yaml` rather than a doctored copy. Two
  guards keep the hand-written half honest — every compose service must
  appear in the registry, and no entry may claim a variable nothing
  delivers, so an over-broad entry cannot silence a real surplus.
- **The PII detector fails closed (blueprint S4c, gap H15).** Stage 3 of
  `pii_service.redact` — Presidio's named-entity pass — is the only
  stage that finds a person, a place or an organisation, and when it
  could not run the module returned its input and `redact` carried on
  through the regex stages. A missing spaCy model or one raising
  `analyze` therefore deleted those classes from *every* attach point —
  intake, the preview, the upload, the run boundary, the MCP `redact`
  tool, the telemetry walks, the gateway's outbound redaction — with
  nothing said anywhere, and no test could tell the two worlds apart:
  regex-only redaction looks like successful redaction. The PRD chose
  that in April (P-10, now marked superseded); CLAUDE.md's "unredacted
  content never touches the database" cannot coexist with it.
  The detector now has a readiness state — `ready`, `unavailable` (the
  constructor failed, with the exception's class) or `failed` (a call
  raised, with the count) — warmed in the backend's and the gateway's
  lifespans, so `GET /api/v1/health` and the gateway's `/healthz` report
  a state that was *measured* by a probe rather than assumed on the
  first call. `failed` clears when a call succeeds again and keeps its
  count: each call fails closed on its own, so one transient fault must
  not become an outage only a restart can end. Outside `ready` every
  content redaction raises, and each attach point turns that into its
  own refusal: `503 pii_detector_unavailable` at intake, the preview and
  the upload (the intake gate is unconditional, so a payload with no
  `x-pii` field cannot create a run either); a `PiiRefused` at the run
  boundary, in the shape `pii_in_output` already had, so the runner ends
  the run `error` with nothing persisted; JSON-RPC `-32004` from the MCP
  tool, which the SDK raises as `PiiUnavailable`; a stripped span and a
  dropped log record on the way out, the H9 shape; and a 503 with a code
  an OpenAI client can read from the gateway. The refusal names the
  state and the attach point and never the text.
  `LIBRERUN_PII_ALLOW_DEGRADED=true` is the operator's explicit opt-out,
  restoring the regex-only pass-through — announced on the platform
  plane at startup, stamped `librerun.pii.degraded=true` on every span
  and record it touched, and written as a `pii_detector_degraded` audit
  row for the tenant it served that way (migration `0016`, throttled per
  tenant so a broken detector cannot write one row per line). Every
  attach point has an injected-failure test in
  `backend/tests/test_pii_fail_closed.py` and the gateway's in
  `services/gateway/tests/test_pii_detector_state.py`; the negative
  probe removes the policy and asserts the fixture's name reaches a
  `runs` row. The backend suite, `chassis-zero-agents` and
  `adapter-battery` now install the spaCy model — without it the
  platform refuses everything, so those jobs were measuring a chassis in
  refusal — which is also the first time the backend suite has exercised
  stage 3 at all. Found while writing the tests and fixed here: the OTLP
  walk discarded the flag from three CONTENT positions (a span's name, a
  span event's name, a log record's `severity_text`), and `gateway.yml`'s
  "the redactor really has its NER stage" step asserted
  `_get_presidio() is not None` against a function that returns a pair,
  so it could not fail.
- **Your telemetry, in the tool you already use: Datadog, Elastic and
  Splunk overlays.** One line in `.env` — `LIBRERUN_OBS_VENDOR=datadog`,
  `elastic` or `splunk` — plus that vendor's endpoints and credentials in
  a new `observability.env`, and `./compose.sh --profile obs up -d`. Each
  overlay carries **both legs** for **both planes**: logs through the
  intake the vendor documents (`datadog_logs` → `/api/v2/logs`,
  `elasticsearch` → `/_bulk` data streams, `splunk_hec_logs` →
  `/services/collector/event`), traces as wire-shaped OTLP/JSON into the
  bundled `otel-bridge`, which re-exports OTLP **protobuf** with that
  vendor's own auth header — Splunk's `/v2/trace/otlp` documents
  protobuf, and Vector cannot emit it, which is why the bridge is
  load-bearing rather than tidy. Resource identity is carried across
  intact, so `service.name` stays `librerun-backend`, `librerun-web` or
  the agent's own. **The overlays forward and never redact**: both planes
  reach Vector already walked, and a second redactor at the edge would
  only be a weaker copy of the first.

  The vendor's credentials live in `observability.env`, loaded with
  `env_file: required: false` on `vector` and `otel-bridge` **alone**, so
  the backend, the gateway and the frontend never hold somebody else's
  API key. With no vendor selected — the shipped default — nothing
  changes: Vector runs its base config, the bundled Jaeger viewer behaves
  exactly as before, and nothing is forwarded. An unknown value is
  refused rather than guessed at: it names a config file that is not
  mounted, so Vector and the bridge stop and say which one they wanted.
  **Admin → Observability** (`GET /api/v1/admin/otel-status`) names the
  active overlay, the configs it loads, the sinks those configs declare
  and whether the backend can still reach the router — each labelled for
  what it is, because the sink list is the overlay's declaration and not
  a read-back from Vector, whose API is loopback-only inside its own
  container by design.

  `obs-vendors.yml` is the evidence. Every overlay must pass `vector
  validate`, and a deliberately broken one must fail it — twice, in the
  two shapes that happen. Per vendor, CI boots the stack, runs a keyless
  demo run and **decodes what a mock intake actually received**: the
  documented envelope, the `service.name` resource identity, and this
  run's trace id — so a transform emitting a perfectly valid envelope
  with the resource attributes dropped fails, and a missing trace leg
  cannot pass on the strength of its logs. S4's raw-instrumentation
  fixture — the address the reference agent emits through its own spans,
  attributes, events and log records — is refused on the raw **bytes** of
  both legs at every vendor. The checker's own rules are negative-tested

  violation, because on a clean capture a working checker and a broken
  one both print OK. **What the mocks prove is the wire shape LibreRun
  emits, not a vendor's acceptance of your data** — said in the workflow,
  in the mock and in `docs/platform/Observability.md`, because a green
  tick is easy to over-read.

### Removed
- **The CI OTEL trace export is retired, not fixed.** Groundcover is not
  a supported vendor (JR, 2026-09-20), so the workflow that shipped every
  CI run's timings to it — red since 2026-08-17, 2,346 failures, root
  cause never established from outside the action — is deleted along with
  the diagnosis steps added to it, its census in
  `backend/tests/test_adapter_kit.py`
  (`test_every_workflow_is_exported_as_a_trace` and the rule behind it)
  and every operational reference to the two repository secrets it used.
  The `.yaml` blind-spot property that census happened to carry is not
  lost: it is now asserted against `_workflow_files` itself, which is
  what every remaining census actually calls. The CI smoke's own trace
  assertion against the Jaeger in the box remains the export proof.
- **A secret can be a file now — `<NAME>_FILE` — and a gate that proves
  none of them leaks (K2).** Docker secrets, Podman secrets and
  Kubernetes' mounted secrets all deliver a value by writing it to a
  file and naming the path in a variable; LibreRun reads that convention
  directly, in both settings models, through one shared helper
  (`backend/app/secret_files.py`, which the gateway image already copies
  along with the redaction pipeline). Set `X_FILE`, leave `X` blank, and
  the value is the file's contents with **one** trailing newline removed
  — one, because `printf` writes one and every editor adds one, and a
  session key ending in `\n` works until somebody rotates it by hand.
  Set both to different values and the process refuses to start,
  `SecretSourceConflict`, naming the variable and never a value: two
  sources disagreeing about one secret is not something to resolve by
  inventing a precedence, since one of them is what the operator meant
  and there is no way to tell which. An unreadable path is refused as a
  path, at start, rather than as "your secret is empty" three layers
  downstream. The value reaches the settings model and **never**
  `os.environ`, which is the whole difference from an entrypoint that
  does `export X=$(cat …)`: `docker inspect` shows a container's
  environment.
  Every secret field on both models is a pydantic `SecretStr`, so a
  settings dump — a log line, a traceback, `print(settings)` in a
  debugging session — prints `**********` and the value is revealed only
  at its use site. Two exceptions are named rather than forgotten:
  `TAVILY_API_KEY` is masked but has no `_FILE` companion, because the
  demo agent reads it from `os.environ` itself and a file would bind a
  value the agent never sees; `POSTGRES_PASSWORD_FILE` is the Postgres
  image's own convention and is documented beside it. A guard fails the
  suite when a field that *looks* like a credential is declared as
  neither, so the next one cannot be forgotten quietly.
  `SecretSourceConflict` is deliberately not a `ValueError`: pydantic
  turns one of those into a `ValidationError` that renders the
  validator's whole input — every merged settings value — as
  `input_value=`, so the exception written to protect a secret would
  have printed all of them.
  **Gate S** is the other half: `scripts/secret_sweep.py` boots nothing
  itself but reads fifteen sinks — every container's stdout and stderr,
  every API response body including the error paths, `app_settings`,
  `activity_audit_log`, the users table, a settings dump out of each
  process, the exported trace and every file under `./data` — and fails
  if a canary planted in a secret slot appears in any of them. A sweep
  that reads nothing finds nothing, so it also refuses to pass unless
  every sink came back with bytes in it, a positive control it planted
  through the admin API is found in three of them, and a second run of
  the same script re-verifies the report it wrote, the way
  `scripts/assert_suite_ran.py` re-verifies a suite. The
  `secrets-as-files` job in `librerun-smoke.yml` boots the stack from
  the compose overlay **read out of `docs/Install.md`** — so the recipe
  CI proves and the recipe an operator follows cannot drift — signs in
  with a password that exists only inside `/run/secrets`, runs a whole
  scenario, sweeps, and then injects the leak into four sink classes in
  turn and requires the sweep to go red for each.
- **Two more example containers, and the demo is five agents.**
  `backend/agents/_examples/llamaindex_summarize/` is a two-step
  LlamaIndex `Workflow` on the Python SDK — `extract` then `summarize`,
  each naming its own `llm.steps` entry, so an admin can run one on a
  cheap model and the other on a better one and the run's trace carries
  two costed LLM spans. `backend/agents/_examples/vercel_ai_answer_ts/`
  is the TypeScript reference server: the whole Run Contract in one file
  on `node:http`, with the Vercel AI SDK's `generateText` and one tool,
  and no LibreRun package at all — which is the claim it exists to make,
  since `@librerun/agent` is v1.1. Both build their model client **per
  invocation**, carrying the agent's LibreRun gateway key and that
  invocation's run token, because a client built once at import time
  carries the first run's token into every later run and the gateway
  then resolves the wrong tenant's configuration. Neither holds a
  provider key; neither mentions the stub. Both degrade to a
  deterministic answer when no model replies, and both say which of the
  two produced what, so a keyless fixture is never shown as a judgement.
- **`ctx.llm.client()` and `ctx.llm.step()` in the agent SDK.**
  `ctx.llm.complete()` is for a handler that makes its own call; a
  framework makes the call itself and will take only a base URL, a key,
  some headers and a model name. `client()` hands those over for this
  invocation — a frozen `GatewayClient`, so a framework cannot retarget
  it — and `step()` returns the one model string the gateway parses as a
  step id. The agent still names no model: which one answers is the
  tenant admin's configuration, resolved per request.
  `docs/authoring/SDK.md` documents the door and the per-invocation
  rule, and drops the sentence that said the SDK exposed no such
  thing — true when S4b wrote it, false the moment this landed.
- **The container battery is a matrix over all three example
  containers**, each entry declaring whether its container exports
  telemetry, with the span verdict held to that declaration in both
  directions — so an entry that stopped exporting cannot turn its own
  check into a skip and pass. The SDK's own suite moved to a job of its
  own and runs once.
- **Two tenants, three containers, one rule.** A new gateway suite
  module drives the real gateway with the real manifests of all three
  shipped examples: with two tenants seeded, each container's call
  resolves the *calling* tenant's model, its agent key alone is refused
  `run_token_required`, and a key for one example presented with another's
  run token is refused. Removing the tenant filter from the gateway's
  step resolver turns all three red.
- **The demo's own claims, asserted in CI.** `GET /api/v1/meta` must list
  exactly five agents — equality, so a sixth fails too. Every card's
  "Try a sample" scenario is then submitted, approved if it parks at a
  gate, and driven to `complete`; each run's trace is read back out of
  Jaeger and **every LLM span in it must carry a model and a cost**,
  which is what separates keyless-and-really-running from
  keyless-and-quietly-doing-nothing. The in-container boundary probe
  (relay and gateway reachable; Vector, Postgres, Redis and the Internet
  refused) now runs inside every agent container, enumerated from the
  `librerun.agent_id` label and written in whichever language that image
  speaks.
- **The LangGraph example calls a model.** It was deterministic end to
  end, so `llm.steps` in its manifest could have produced neither a
  costed span nor a model change from the admin page. Its `classify` and
  `draft` nodes now go through the `llm` capability to the gateway,
  naming a step rather than a model, and the manifest declares both steps
  with their defaults. Each node computes a rule-based answer first and
  uses that one answer twice — as the fallback when the call fails, and
  as the keyless fixture it hands the gateway as `librerun.stub_reply` —
  and the structured output says which source answered, so a fixture is
  never displayed as a judgement — the label is read from the provider
  the gateway names in its reply, not from whether the call succeeded,
  because keyless a fixture comes back as an ordinary successful
  completion and "a call worked" is not "a model decided". A reply is
  validated against the schema the node asked for before it is used —
  `response_format` is a request the gateway forwards, not a guarantee
  it can enforce, and a step retargeted to another provider may honour
  it loosely — so a malformed answer falls back to the rule instead of
  failing the phase. Validation uses the chassis's own
  `Draft202012Validator`, the one `intake.py` already checks agent input
  with, rather than a hand-rolled checker; a test fails if either schema
  declares a keyword JSON Schema does not know, since a misspelled bound
  reads like a bound and enforces nothing. A second scenario ships alongside the outage one; it is the case where the keyword rule and a model disagree,
  which is the clearest thing an example can show about why the call is
  there.

  refused by an agent that merely keeps an allowlist of every token it has
  issued, so the battery also mints a second invocation and cross-uses its
  valid token against the first invocation's leaves. Membership is not
  binding, and only a token the agent itself accepted can tell them apart.
  That cross-use runs in both directions, because the leak is directional:
  an agent that hands each invocation a snapshot of the tokens issued so
  far refuses the second invocation's token on the first and accepts the
  first's on the second, so probing one way certified it clean while one
  invocation's own token fetched the other's output. It runs once the
  first invocation has finished rather than beside it, which is how the
  chassis drives an agent anyway — one invocation per phase, parking
  between them — so an agent that serves one at a time is no longer asked
  for a concurrency the contract never promised. And the check is not
  settled until that probe has actually run: an agent that refused the
  second invocation used to be certified with a note attached, and a note
  is not a verdict, so the binding check is now open — and failing — from
  the moment the first four probes land until the cross-use concludes, on
  every path out of the run. Where a second invocation genuinely cannot be
  obtained the result says UNPROVEN rather than pass, naming which of the
  two reasons applies, because an unproven MUST is not a satisfied one.
  The probes themselves read the status line and close the response
  unread: the agent this check exists to catch is the one that accepts a
  foreign bearer on `/events`, and what it hands back is a stream held
  open for the life of the invocation — consuming it took four times the
  hold to reach a verdict the battery already had, and raised a read
  timeout out of the battery entirely when the client timeout was shorter
  than the run. Both invocations run under the **same `run.id`**, the
  second as a rerun, because the chassis sends one run id across a
  two-phase run and across a rerun: starting the second under a different
  run manufactured an isolation the platform never provides, and an agent
  that pools accepted tokens by run rather than by invocation passed on
  the strength of that choice while leaking between two invocations of one
  real run. And a transport failure on that second request is now a
  reported result rather than a traceback — the first request has always
  converted one, and an agent that resets the connection after its first
  invocation is exactly the one whose cross-probe must not escape
  reporting. That rerun carries the user's edits, because the chassis
  derives `rerun` from them — a `true` flag beside a null edit is a pair
  it can never send, and an agent that enforces the relationship was
  answering `400` and being reported UNPROVEN while being right. And no
  binding probe raises any more either: an agent that resets the
  connection rather than answering `401` has failed the obligation just
  as surely as one that answers `200`, so the failure is recorded with
  the transport error named instead of escaping as a traceback. The rerun
  carries the user's edit **text** and the first invocation's output,
  because that is what a real rerun carries — a dict in the edit field
  satisfied the flag and neither the type nor the shape, and an agent
  checking them was refused and then blamed. The battery also drains the
  invocation it starts for that probe, since execution may begin lazily
  when the stream is opened and an abandoned invocation either never runs
  or outlives the battery. And that invocation's telemetry is no longer
  evidence for the one under test: counting it let an agent that
  instruments reruns but not ordinary runs pass the span check while
  exporting nothing for the run being certified. The second invocation is
  chosen from the **manifest** rather than assumed: the next phase of the
  same run where a later phase exists, a second run where none does. A
  rerun is not a transition every manifest can make — an edit is accepted
  only while a run is parked awaiting approval, and only a later gated
  phase parks it — so a single-phase agent was being sent a request the
  chassis could never send it, and refusing it correctly was being
  reported as a defect. Deriving the transition removed the invented edit
  text altogether. An invocation whose own token is refused by its own
  events stream now fails rather than being noted, because the chassis
  could not have consumed it; the trace-integrity check covers everything
  the agent exported while the evidence check stays scoped to the run
  under test; and the settle wait is for that run's telemetry, not for
  whatever reaches the relay first. A phase followed by an approval gate
  has **two** transitions the chassis can make — the next phase and a
  rerun of this one — and the battery runs both, because a rerun holds the
  phase constant as well as the run and so catches token pools keyed on
  the pair; both shipped multi-phase manifests are that shape. Trace
  integrity is checked even when the run under test exported nothing,
  since a wrong-trace span from the binding invocation is telemetry the
  relay would refuse either way, and the settle window covers every
  invocation the battery started rather than only the first. The probes
  close their connections: one that abandons an unread event stream must
  not return to the pool, where the next probe queues behind a server
  still holding it and times out on a response it already had.
  Those two transitions run in the only ORDER the chassis can produce
  them — the rerun first, then the gate — because completing the final
  phase ends the run and an edit is accepted only while one is parked, so
  asking for a rerun after advancing is a sequence the platform never
  sends and an agent that models its run's lifecycle was refusing it and
  being blamed. Having the rerun first is also what lets the later phase
  receive the **rerun's** output as `prior_output`, which is what the
  chassis supplies once a rerun has written the snapshot. And the settle
  window is measured from the latest telemetry to arrive rather than from
  the first batch each token sends: an invocation that exported a correct
  batch promptly and a wrong-trace one later escaped a check that had
  already stopped watching, though the relay would refuse it and the
  contract explicitly allows a flush that straddles `completed`. The
  window is capped, and reaching that cap while telemetry is still
  arriving does not certify the agent: the spans check reports
  `incomplete` and names the remedy, because an open check is a failing
  check and a bounded check that reports a settled verdict over a moving
  target is the same defect wearing a note. The sequence also follows the
  run's own state: a phase invocation that ends `failed` sets the run to
  error, so nothing follows it there, and the battery that drained such a
  rerun and advanced the same run anyway was blaming an agent for refusing
  a transition the platform could not have made. But that run being over
  does not make the later phase unreachable — a gated phase is also
  reached by the user approving the original invocation rather than
  editing it — so the battery re-anchors on a fresh run whose phase
  succeeded and probes the rest there. Stopping instead certified an agent
  whose reruns are correct and whose ordinary next-phase invocations pool
  tokens by run id. An agent that will not start that fresh run leaves the
  check unconcluded for the transitions it was carrying, which is a
  failure naming the reason rather than a pass.
  Each cross-use is recorded
  under a case naming its transition, because one shared name let the next
  phase's refusal overwrite the rerun's leak. A log record arriving under a
  token the battery never minted now fails the check as a span would: the
  relay authenticates both the same way. And every invocation carries its
  own phase's `deadline_seconds` from the manifest rather than the
  battery's HTTP timeout, which is a budget the chassis cannot produce —
  an agent that declares 30s was handed 120 and refused it at the first
  request.
  Every invocation the battery starts is cross-used against every other
  in both directions, because "bound to its invocation" is a claim about
  each pair: anchoring the cross-use left the rerun/next-phase pair
  unasked, and an agent accepting whichever token immediately preceded it
  answered 401 to everything else and passed. A `completed` event need not
  carry its output inline — the contract puts it at `/output` and the
  chassis fetches it there — so the battery resolves that fallback before
  handing the result to the following phase, rather than passing on a
  stale one. And it never advertises a budget it will not wait for, nor
  waits past one it advertised: `--timeout` is the battery's own
  `LIBRERUN_MAX_PHASE_SECONDS` in both directions. It is passed *as* the
  ceiling to the chassis's own resolver rather than applied as a second
  clamp after it — composing the two meant the importing process's
  ceiling had already won, so the flag could only ever lower the
  advertised budget and an agent whose phases legitimately outlast that
  ceiling could not be tested at all. And the number is now enforced on
  the wall clock, not merely printed: an HTTP read timeout bounds the gap
  between chunks, so an agent that keeps emitting progress was waited on
  indefinitely while production would have cancelled it at the deadline
  and ended the run. Each events stream is read under that invocation's
  own budget — the phase's, not the first phase's, since a drained
  next-phase invocation carries its own — and overrunning it is a
  recorded failure naming the deadline, the way the chassis fails a run
  `PhaseDeadlineExceeded`. That budget spans the whole exchange rather
  than the stream alone — the POST that starts the invocation and the
  `/output` fetch that ends it are inside it too, since production wraps
  all three in one `asyncio.timeout`; bounding only the middle left an
  agent sleeping eight seconds in the POST to pass a two-second deadline
  after twenty-five. It is carried across those legs, not restarted at
  each, so an invocation cannot spend its whole budget three times over;
  and it excludes the battery's own binding probes, which production
  never makes and which an agent must not be charged for. A `--timeout`
  below one second is refused rather than rounded: `deadline_seconds` is
  an integer on the wire, so a sub-second ceiling would advertise more
  time than it enforces.
  `/healthz` belongs to each invocation and to that invocation's budget,
  because the chassis probes health before every phase it starts and
  inside that phase's deadline: probing once per run certified an agent
  that stopped answering after its first invocation, and probing outside
  the clock gave a slow `/healthz` away for free. The battery's own
  binding probes run *beside* the events stream rather than between the
  POST and the read, and they are collected after the invocation's last
  leg rather than between the stream and the `/output` fetch, so they
  neither pause the invocation's clock nor spend it — waiting for them
  mid-exchange failed an agent whose own POST, stream and `/output` took
  1.0s of a 5s deadline, for a request the battery never got as far as
  making — and they ask the agent for no concurrency it does not
  already have, since one that will not answer while streaming simply
  answers when the stream ends, outside the deadline. A probe that does
  not answer in time is now a failure carrying its own name: collecting
  them under a deadline meant a cancelled probe wrote no result and
  vanished from the verdict, which then read `token_binding: pass` on a
  check that ran on half of what it claims to cover. Every probe is
  named before any of them runs. And the two questions that need no
  token the agent issued — no bearer at all, and one the battery invented —
  are put to **every** invocation the battery starts rather than only
  the first: an agent whose later invocations check `if header and
  header != expected` refuses every bearer this battery could show them,
  and serves their `events` and `output` to a request carrying no bearer
  at all. And an invocation the battery starts counts as one the chassis
  could have consumed only if its result could actually be obtained: a
  `completed` carrying no inline output sends the battery to `/output`,
  exactly as production goes there, and a fetch that answers non-200,
  answers with a body that is not JSON, answers with an `output` that is
  not an object, fails at the transport, or outruns the phase is now a
  named failure rather than a silently empty result — production raises
  `ContainerAgentError` for each of the first four. Measured before the
  fix: an agent correct on its first invocation and on every token,
  whose second invocation could not serve its result, passed the whole
  battery three times over, once for each shape of that failure. The
  recovery path that starts a fresh run to replace a failed transition
  is held to the same rule, and the report distinguishes a run that was
  refused from one that started and then could not produce a result. Two
  more contract rules apply to those invocations as they do in
  production: a stream that ends with neither `completed` nor `failed` is
  an invocation the chassis could not have consumed rather than one the
  battery drained, and a `completed` carrying a non-object `output` — say
  `[]` — is a failure rather than a reason to go looking at `/output`,
  which is what the chassis does with it. Both passed the battery
  before. And every probe batch is bounded, including the third: the
  recovery path's cross-use was awaited with no bound at all, so an agent
  that accepts a connection and never answers cost the client timeout
  once per probe — measured at 84s against a 2s timeout, which at a
  production timeout is hours of hanging instead of the failing verdict
  that was due. And every invocation is sent the trace context the chassis
  would have sent it — its run's trace id under a fresh parent span, and a
  new trace id for a new run — rather than one `traceparent` replayed at
  all of them: a stateful agent that refuses to be handed the same parent
  span twice was answering `400` and being reported UNPROVEN for a request
  shape production never produces. The span check follows: a span is on
  the right trace when it matches the trace sent to the invocation whose
  token it arrived under, which also catches a span on the right trace for
  the wrong invocation. Every invocation's output is boundary-walked, not
  just the one under test: the chassis walks each phase's terminal output
  before persisting it and ends the run `error` with `pii_in_output` when
  it refuses, and an agent whose second invocation — or whose fresh anchor,
  whose output is carried into the next phase — returned a Luhn-valid card
  number as a JSON number used to pass the battery clean. The failure
  names the kind, the path and the PII type, never the value, and says
  which consequence production would reach: `ContainerAgentError` for a
  contract violation, `pii_in_output` for an output it will not persist.
  That walk runs off the event loop and its walker is warmed before any
  invocation starts, because the first call loads models — 3.4 seconds,
  then four milliseconds — and paying that in the middle of a run starved
  the probes in flight on the same loop, which CI caught as a connect
  timeout with every check otherwise passing. A heartbeat test now fails
  if the battery blocks its own loop for more than a second and a half.
  What the walk RETURNS is what moves forward, too: the chassis replaces
  a phase's output with the walked value before persisting it, so the
  next phase's `prior_output` carries placeholders where the walk
  redacted, and the battery was carrying the original — a `prior_output`
  production never sends, which a stateful agent validating its input can
  reject. And the telemetry snapshot is taken at the verified quiet
  point: an unconditional 0.2-second sleep used to admit arrivals that
  had never been given the settle window, so a batch landing in it could
  be followed, inside that window but after the snapshot, by one nobody
  looked for.
  And the battery walks the whole sequence of phases the chassis would
  reach, not one step of it. The runner loops until a failure, a gate, or
  the last phase, so an ungated manifest runs every phase in a single run
  with no human in between, and a gate stops the run rather than the
  sequence — the user approves and it carries on. Planning only the next
  phase certified everything past it unseen: an agent bound per
  invocation for its first two invocations and pooling tokens by `run.id`
  from the third passed with `token_binding: pass` and no failures at
  all, while that third invocation's `events` and `output` answered any
  token the run had issued. Each phase is now probed under its own name,
  so a report says `the third phase` rather than `the next phase`. A
  walk that loses its run to a failed phase is held to what the
  replacement run can actually produce: that run has only the phase under
  test completed in it, so the battery carries on there only for the
  transition that follows it and otherwise stops and says so, rather than
  asking for a phase whose predecessor never ran — which would fail an
  agent for refusing a sequence the chassis cannot produce.
  Terminal events are read the way the chassis reads them, on every
  stream rather than only the first invocation's. The chassis returns at
  the first `completed` or `failed` it parses and the contract allows
  exactly one, but the two streams added as the battery grew each asked
  whether a `completed` appeared *anywhere* and whether a `failed`
  appeared *at all* — so a `completed` followed by a stray `failed` read
  as a phase that both succeeded and died. Measured: the battery stopped
  a three-phase walk after the second phase, reporting `passed: True`
  about a run the chassis carries straight through. One helper now states
  the rule for all three streams, the first terminal decides, and a
  second one is reported as what it is — a contract violation production
  consumes without complaint, so nothing downstream would ever surface
  it, and telling an author it raises `ContainerAgentError` would send
  them hunting an exception that is never thrown.
  And a frame the chassis dies on is not a frame. The chassis raises while
  PARSING an event whose data is not JSON, or is JSON but not an object,
  so it never reaches the terminal or the `/output` fallback — but the
  battery's parser substituted a placeholder dictionary for the first,
  letting a malformed `completed` fall through to a valid `/output` and
  pass, and handed the second back unchanged in defiance of its own
  signature, so `data: 42` raised an `AttributeError` out of the battery
  where a verdict was due. Every event is parsed in production, so a
  malformed progress line is equally fatal and was never looked at. The
  parser now marks what the chassis would have raised on, and the terminal
  check reads every frame rather than only the terminal ones.
  That assumption lives at every JSON boundary, not only in the parser. A
  decoded body is assumed to be an object at six call sites, and `.json()`
  succeeds for an array, a number or a string exactly as for an object, so
  an agent answering one of those where an object was due crashed the
  battery instead of being reported non-conformant — seven of the eight
  shapes raised rather than returning a verdict, including on the very
  first invocation. One helper now decodes and validates, and no raw
  decode remains. A frame carrying data with no event name is also parsed
  in production and dies there, so the battery no longer discards it.
  And a binding probe is bounded as the probe it is. The probes of a plan
  are sent one after another, but the whole plan was bounded as though it
  were a single request, so a conforming agent answering each refusal in a
  third of a second was failed under a two-second timeout purely because
  twelve of them do not fit one window — and plans grow with every prior
  invocation. A probe now has its own ceiling, on the same footing as the
  health check, because a probe is not the agent's phase and the phase
  deadline is the wrong ceiling for it; the batch is bounded on having
  stopped answering rather than on a total, which needs no count of a plan
  that has not started yet. A hanging agent is caught the same way as
  before and reports more: every probe names its own reason instead of a
  batch collapsing into a single line.
  The invocation the battery starts to recover from a failed transition is
  cross-used like any other — it was being remembered without being
  probed, so the one invocation the recovery path creates was exempt from
  the guarantee every other one carries — and it may name itself with the
  pre-v1.1 `run_id`, which the rest of the client already accepts. The
  `--timeout` the authoring guide tells authors to raise now exists on the
  command line it names.
  And the probe that starts a run of its own is not cancelled by the run
  before it. A `failed` phase legally ends the run the walk was
  advancing, and the battery subtracts the transitions it can no longer
  reach — but the second run of the phase under test, added so that a
  cross-use pair exists which does not cross a phase boundary, starts a
  run of its own and nothing that happens to the first can make it
  unproducible. It sat last in the same list and was being subtracted
  with the rest: measured on a two-phase manifest whose second phase
  answers `failed`, the battery reported `token_binding: pass` with no
  failures and never sent the probe, while a second run made by hand read
  the first invocation's `/output` with `200`. The walk's own transitions
  and the run-scoped ones are now counted apart, and the end of a run is
  reported either way rather than passing in silence.
  And the replacement run is DRIVEN to where the plan needs it, not
  assumed to reach one phase. A `failed` phase ends its run, but the
  phases behind it are not necessarily out of reach: a user starts
  another run, replays the prefix and approves rather than editing. The
  battery started a replacement run, drove its first phase and subtracted
  everything the plan needed further along — the helper's reach standing
  in for the chassis's. Measured on a four-phase manifest with a gate,
  whose rerun ends `failed`, against an agent bound per invocation
  everywhere that plan looked and pooling tokens by `run.id` from the
  third phase on: `token_binding: pass` with no failures at all, the
  third and fourth phases never invoked, while a real replacement run
  that replayed the prefix read the first invocation's token into the
  third phase's `/output` with `200`. Each transition now states which
  phase a replacement run must reach before it can be produced, the
  replacement is driven leg by leg up to it, and every leg is cross-used
  as it starts rather than only the last. Only a replacement run the
  agent will not drive that far shortens the plan, and the report then
  says how far it got and what stopped it.
  And a replay leg that does not complete is not the same as one that
  fails. A phase is allowed to end `failed` — that is the agent's
  prerogative, it shortens the plan and it is not charged to anyone — but
  a leg that answers 500, outruns its deadline, sends two terminal events
  or produces an output the chassis could not have read is an invocation
  the chassis can produce and could not consume, which is a check that
  did not conclude. All of them were treated alike: measured, an agent
  answering 500 on the replacement run's second phase took
  `token_binding: pass` with no failures, over a report whose sentence
  ended in `None` because the path that gave up never said why. Every
  such leg now names its reason and only a valid `failed` terminal
  shortens anything. A leg that does end `failed` is cross-used like any
  other invocation, too: it used to return before the probes, so an
  invocation the battery had started and the agent had issued a token for
  was remembered without ever being tested — an agent whose failed leg
  answered every token it had issued passed clean.
  And the chassis no longer cuts a phase short of its own deadline. The
  container client's read timeout was the constant 600 seconds while a
  phase's deadline is configurable to `LIBRERUN_MAX_PHASE_SECONDS`
  (3600), so an agent that emitted one `progress` event and then worked
  silently for longer than ten minutes — legal, inside a deadline that
  allows it — died at the transport, and the run named a read timeout
  instead of the phase. The runner already applies the opposite rule to
  model calls, deriving their transport ceiling from what is left of the
  step's own timeout so the client can never hang up on a call the step
  still allows; the container client was the one place that had not
  adopted it. The ceiling now comes from the invocation's deadline, the
  runner's cancellation is still the single enforcement point, and the
  Run Contract says plainly that going quiet costs nothing the deadline
  permits.

### S4a — The LLM gateway: one door to every model
- **`services/gateway/`, a service of its own** (L23, L24): every model
  call an agent makes arrives here as an OpenAI-compatible request —
  in process, in a container, on the SDK, or from a framework that only
  knows `OPENAI_BASE_URL`. It is separate on purpose: egress code inside
  the backend would keep provider credentials in the one process every
  `python-package` agent shares.
- **No provider key in the backend.** `credential()` is gone from the
  `llm` capability, `openai`/`anthropic`/`google-genai` left
  `backend/requirements.txt`, and the provider keys and
  `LIBRERUN_STUB_LLM` left the backend's compose environment for the
  gateway's. The demo agent's three provider SDK integrations are
  deleted; it names a step and the platform decides the rest. The three
  key fields are gone from `backend/app/config.py` too: that model reads
  the repository-root `.env`, so declaring them was enough to
  materialise the real values into the backend process in the documented
  local dev mode, where any in-process agent could read them by
  importing `app.config`. The process also says so at boot if one is in
  its environment anyway, by variable name and never by value.
- **A restart no longer leaves stale agent authorization.** If the
  database was unreachable at boot, the backend logged a warning and
  never tried again — so an agent that had been uninstalled, or had its
  `llm` grant revoked, kept authorizing model calls from the previous
  boot's rows for the life of the process. It retries until the current
  discovery is persisted.
- **Keyless embeddings answer at the width requested.** `dimensions` is
  forwarded to a real provider and was ignored by the stub, which always
  returned sixteen — the wrong shape in the demo, and incompatible with
  a knowledge index whose model is a different width.
- **Every forwarded parameter now has a decided keyless behaviour, and
  the build enforces it.** A parameter the gateway hands to a real
  provider and the stub quietly drops is wiring that keyless mode does
  not prove: the agent is written against one contract and deployed
  against another. Three more were found this way — `n` (the stub
  returned one choice however many were asked for, in the body and in
  the stream), `encoding_format` (floats however `base64` was asked
  for, which the official OpenAI client requests by default when numpy
  is installed), and the legacy `functions`/`function_call` spelling (a
  forced call answered with prose, so a client waiting for a call
  waited forever). The rule applied is *honour what changes an agent's
  control flow, document what only changes detail*, and a table over
  both allowlists fails the build when a forwarded name carries neither.
- **Synthesised numbers respect exclusive bounds.** A schema with
  `exclusiveMaximum` was answered with exactly that value — the one
  number it forbids — and a range no value can satisfy is now refused
  by path (`schema_unsatisfiable`) rather than answered with something
  the caller's own validator rejects. At large magnitudes `bound ± 1.0`
  rounds straight back onto the endpoint (`1e20 + 1.0 == 1e20`), so the
  step falls back to the next representable float, and one postcondition
  covers every path rather than only two-sided ranges.
- **A bound too large for a float no longer answers with a 500.** An
  integer bound is exact and unbounded in Python, so a 400-digit
  `minimum` on an `integer` schema is honoured; on a `number` it means
  an infinity no float can satisfy, and is refused by path. Previously
  one raised `OverflowError` and the other returned a value.
- **The agent SDK takes no per-call `timeout`.** It replaced the
  invocation's transport budget outright, so a value shorter than the
  configured step timeout closed the client socket while the gateway
  went on running and billing the provider call — the failure the
  budget-derived ceiling exists to prevent. Passing one now raises with
  the reason, rather than being silently stripped downstream.
- **Streamed keyless replies carry their logprobs.** The non-streaming
  reply filled `choice.logprobs` and the stream dropped it, so a
  streaming client saw an absent field that a credentialled provider
  supplies.
- **Required keys are emitted whether or not `properties` describes
  them.** `{"type":"object","required":["x"]}` answered `{}`, failing
  its own validation; an unconstrained required key is not an absent one.
- **A `default` is used only when it fits.** JSON Schema's `default` is
  an annotation and need not satisfy its schema, so returning it
  unchecked answered `{"type":"integer","default":"unknown"}` with a
  string.
- **`oneOf` and `anyOf` keep the constraints beside them**, and a
  `oneOf` value now satisfies exactly one branch rather than merely the
  first — a value valid under two is rejected by a strict validator.
- **A deeply nested value is refused rather than crashing the process.**
  Comparing or checking enum values walked the request body to Python's
  recursion limit, raising an uncaught `RecursionError` at around 900
  levels; both are depth-bounded and refuse with `schema_too_large`.
- **A union `type` is satisfied by any of its members.** An enum
  candidate was checked against the first declared type only, so
  `{"type": ["string","integer"], "enum": [1]}` was refused although it
  is satisfiable.
- **An enum candidate that is a container is checked inside.** An array
  candidate is measured against `items` and an object against its
  `properties` and `required`, so an enum of containers no longer
  answers with one its own siblings forbid.
- **The merge's work budget is shared across the whole merge.** A cap
  recreated per intersection resets on every call, so a schema could
  keep each one under it while the total grew without limit; the budget
  now spans the merge and covers building the comparison index as well
  as searching it.
- **A type union keeps every overlap.** An exact match no longer hides
  the `number`/`integer` subtype overlap beside it.
- **A combinator nested in an `allOf` branch is searched, not
  collapsed**, and an option that cannot be synthesised is skipped
  rather than aborting the search — a contradictory alternative is not a
  contradictory schema.
- **A composed schema can no longer stall the gateway.** Intersecting
  two `allOf` enums compared every value against every other, so two
  disjoint 5,000-element lists took 7.3 seconds on the event loop from a
  single request — the node budget never saw it, because the work
  happens during the merge. Scalars are indexed by a type-tagged key
  (0.003s for the same input); the unhashable remainder is compared
  under a budget.
- **`anyOf` picks an option that works.** When a parent constraint
  contradicts the first alternative, the next one is tried rather than
  synthesised regardless.
- **`allOf` merges item schemas and narrows declared types.** Two
  branches describing one array's items compose like two branches
  describing one property, and `number` with `integer` narrows to
  `integer` instead of keeping whichever came first.
- **One work allowance per request, not one per branch.** The budget was
  shared across a merge but every combinator option was merged without
  it, so each option took a fresh allowance: a 9,000-member parent enum
  against 2,000 disjoint options blocked the gateway's event loop for
  4.4 seconds on an ~11,000-node schema. Options are now merged one at a
  time under the caller's budget — lazily, because merging them all up
  front under one shared allowance would refuse schemas that answer
  today, and an over-eager refusal is the worse failure.
- **Every nested combinator is carried, not just the first.** An `allOf`
  whose branches each declared an `anyOf` kept one and dropped the rest
  silently, answering with a value that satisfied the first group and
  violated the second. The groups distribute into the merged
  combinations, impossible pairings are dropped rather than coerced into
  a coherent-looking type, and a `oneOf` among several groups is refused
  by name — "exactly one option matches" does not survive distribution,
  and a stub that declines a shape is recoverable where one that answers
  wrongly teaches an author their schema holds when it does not.
- **`oneOf` counts a branch it can actually evaluate.** The
  match-counter asked `_satisfies`, which ignored `enum` and `const`
  entirely, so every enum-only branch looked satisfied by every value:
  a `oneOf` over `[1]` and `[2, 1]` answered `1`, which matches both
  branches and is invalid, while `2` matches exactly one. Both keywords
  are checked now — being unable to evaluate a keyword is a reason not
  to reject on it, not a reason to skip one that is understood.
- **A choice with a valid arm is taken, not settled.** Three places
  returned a fixture the schema rejects while a satisfying one was
  available: `oneOf` never looked past a branch's first value, so a
  nested alternative matching exactly one branch went unseen; a type
  union committed to its first non-null member without asking whether
  that member's constraints were satisfiable (`{"type":["string",
  "integer"],"minLength":2,"maxLength":1}` answered a one-character
  string, though the length keywords do not apply to an integer at all);
  and an optional property was emitted even when its own subschema could
  not be met, making an object invalid that was valid as `{}`. Where the
  schema genuinely offers no way out the behaviour is unchanged — a
  required key with impossible bounds is still filled, and a union no
  member satisfies still answers — because that contradiction is the
  caller's and inventing a refusal for it helps nobody.
- **A sibling combinator supplies candidates one level down, not only
  vetoes them.** Building a branch stripped both `oneOf` and `anyOf` and
  then expanded one of them, so a nested sibling could reject every
  candidate and never offer one: `{"oneOf":[{"oneOf":[{"type":"integer"},
  {"type":"string"}],"anyOf":[{"const":2}]},{"type":"integer","enum":
  ["x"]}]}` fell back to `0`, which matches neither arm, though `2`
  satisfies the schema. The sibling's own options are now a candidate
  source — with their own allowance, so the arms cannot spend it before
  the sibling gets a turn; merged on a copy of the budget, so a failed
  merge cannot bankrupt the search; and filtered against the whole schema,
  so a seed no arm can accept never becomes the answer. A seed that filter
  rejects gives its slot back, under a bound of its own — a rejected
  candidate has told the search nothing, and unbounded refunds would turn
  the search into a scan.
- **A numeric leaf offers its neighbours, integral and fractional.** `1.0` is an integer
  in JSON Schema, so for `{"oneOf":[{"type":"number"},{"type":"integer"}]}`
  every integral value matches both arms and none is exclusive — the search
  was correct and had nothing left to consider, returning `0.0`, which the
  schema rejects, though `0.5` satisfies exactly the `number` arm. The
  non-integral candidates have an allowance of their own, so widening the
  search here does not narrow it for a `oneOf` crowded with numeric arms —
  with bounded refunds, because that allowance is spent before the outer
  combinator judges the value, and a candidate the consumer rejects has
  told the search nothing, and every offset is offered rather than the
  first one only — including a different integer, which is the only kind of
  neighbour an `integer` arm can accept. The walk steps outward past
  neighbours the competing branch already occupies, bounded twice over —
  how far one leaf may walk, and how much of the shared allowance it may
  take — and stops at the first ring its own schema refuses. At magnitudes
  where a fixed offset vanishes into the float's own precision it steps to
  the next representable value instead, as the bound stepper already did,
  while an integer leaf keeps its exact steps — decided before the addition,
  since an int past the float range cannot be added to a fraction at all.
  At those magnitudes both offsets in a ring land on the same representable
  value, and a candidate the search has already offered no longer spends
  the capacity meant for a new one — in the walk, in an enum leaf whose
  members repeat, and across arms that each synthesise the same value.
  A candidate claimed for a branch that then turns it down gets the claim
  back, as it already got the capacity back. Lists and objects are
  candidates like any other, so the value index keys them recursively
  rather than calling every copy new — which is also what stopped the
  enum intersection comparing containers pairwise. Keying a container is
  a walk proportional to its size, so it is memoised for the request and
  charged per member: a repeat costs nothing, and a wide value cannot
  buy unbounded synchronous work — including under a speculative merge,
  which keeps its own node count and shares everything else, so a walk
  under a merge that is later thrown away is still a walk that happened —
  and a merge that runs the request out of value work says so rather than
  being mistaken for one option being too big to build. A value JSON cannot write is not an
  answer either — `1e999` parses to infinity and `json.dumps` spells
  that `Infinity`, so such a candidate is skipped where another will do
  and refused where none will, at every depth of a container. Every candidate
  allowance in the module is paired with a bounded refund, and the suite
  carries the census that says so.
- **The choice is searched wherever there is one.** A leaf with several
  permitted values offers all of them, not just the one picked; a boolean
  leaf offers its other value, since two is a choice like any other; a
  leaf whose `type` is a union offers a value of every member it
  declares, since the union is the choice — once each however often the
  schema repeats it and in time linear in the names declared, built
  speculatively so a member too big to construct costs the search nothing
  rather than refusing it, bounded so that discarding one cannot be made
  to cost the service without limit, by a bound that narrows what a
  speculative build may spend rather than deciding which members are
  considered at all — with the live budget charged for what such a build
  actually spent rather than left holding whatever the narrowed probe had
  over — and refunded when the context rejects it, so
  offering one cannot starve the leaf behind it;
  a combination whose types cannot all hold is dropped before it is
  merged, including when the contradiction is nested inside `allOf`
  rather than declared at the top; a nested
  `oneOf` candidate must clear that `oneOf`'s own exclusivity before the
  level above sees it; `null` is the last union member tried rather than
  one filtered out, so a schema satisfied only by `null` gets it; an
  array prefers `[]` over an element its own `items` rejects, as an
  object already preferred omitting an optional property. An option
  whose merge is impossible is skipped rather than aborting the search —
  a property established earlier and lost in a refactor, which left the
  catch in place but no longer around the call that raises.
- **Membership is judged against the option, not the merge.** A branch
  merged with its parent is what a candidate is built from; it is not
  what decides which branch that candidate belongs to. Merging
  `{"type":"string"}` under a parent `{"type":"number"}` keeps the
  parent's type, so a number counted as matching a string alternative,
  and a `oneOf` answered a value satisfying neither of its branches. The
  same test also treated a nested combinator as automatically satisfied,
  accepting a candidate against an option nothing can satisfy. One
  helper now answers every membership question — constraints plus
  combinators, asked of the original option, with the parent checked
  separately.
- **The membership check reaches all the way down and all the way
  across.** It walks a container's own subschemas rather than handing
  the recursion to the checker that has no combinators, so an
  impossible `oneOf` inside a property is seen; and a schema declaring
  two combinators at one level has both enforced, where the second used
  to be stripped and forgotten. The schema a candidate is built from and
  the schema it is judged against are now distinct in this direction
  too.
- **Optional members are judged through their combinators too**, so a
  property or array element whose own `oneOf` nothing can satisfy is
  omitted rather than emitted — and the sibling's candidates get an
  allowance the arms cannot spend, so the source added for schemas only
  it can answer is not crowded out before it contributes.
- **A single-option combinator faces the same checks as any other.** The
  fast path for it skipped the exclusivity count and the sibling check
  both, which is a second implementation rather than a shortcut; it is
  gone, and the sibling's own options now seed the search so an arm that
  cannot take the sibling in its merge can still reach a value the
  sibling permits.
- **Value work is bounded apart from structural work.** The `enum`
  membership test was a linear, recursive scan charged nothing, and it
  runs once per candidate: 32 candidates against a 180,000-value sibling
  enum spent 1.7 seconds and 194 nodes — the time grew with the enum and
  the charge did not move. The stub's synthesis is synchronous end to
  end and nothing can interrupt it, so that was the gateway's event loop
  held by one authenticated request. Membership now goes through the
  same `_key` index the `allOf` intersection already used, built once
  per request and reused. Charging those comparisons to the *node*
  budget is what the first attempt did, and it starved the search:
  schemas that answered correctly began refusing, or returning a value
  the schema rejects. Comparisons have their own allowance underneath
  the node budget.
- **Nor does a contradictory item sink an array that may be empty.** The
  same treatment as the property merge beside it: the constraint is kept
  and `minItems` decides whether it is fatal.
- **A contradictory property no longer sinks the whole object.** Whether
  an unsatisfiable property is fatal is a question about `required`, and
  the synthesiser already answers it — omitting an optional one, failing
  on a required one. Raising from the merge took that decision away.
- **One unusable combination no longer aborts a whole distribution.** The
  `anyOf` cross-product already skipped a combination whose types are
  disjoint; a combination the merge itself declined was fatal instead,
  so a schema refused after a valid product had already been built.
  Budget exhaustion still propagates — that is a fact about the request,
  not about one combination.
- **An option carrying both `oneOf` and `anyOf` is kept, not refused.** A
  single `oneOf` beside `anyOf` groups needs no distribution: it is
  carried as a sibling, a shape the synthesiser already understood. Two
  `oneOf` groups still refuse, because there is no way to carry two
  without asserting an exclusivity nothing has checked.
- **A guard that stopped guarding was caught by the injection audit.**
  Changing the shape of the search meant an earlier release's test no
  longer exercised what it measures: it kept passing on a tree carrying
  the defect it exists to catch. It is re-armed on a construction
  verified to separate. A green suite is not evidence that a guard still
  guards.
- **Candidate capacity is spent only on candidates that are usable.** A
  leaf that could not be built was charged before synthesis could reject
  it, and a candidate the surrounding search rejected for contextual
  reasons kept the slot it had taken — each starving valid values behind
  them. Capacity is charged after a leaf is built and returned when the
  consumer rejects one. The bound on work is the node budget, which every
  membership test charges; the candidate counter bounds only how many
  candidates a branch may offer.
- **A rejected candidate no longer spends candidate capacity.** The
  enum-leaf filter charged the shared limit for every member examined
  rather than every member yielded, so copies of an invalid member
  starved a valid one further down — the threshold sat exactly at the
  cap. The leaf is now judged with the combinator-aware check, and the
  limit is charged on yield; scanning stays bounded because that check
  charges the node budget per call.
- **The inferred type is not the required type — now a rule, not a case.**
  `properties` and `required` constrain object instances and do not
  require the instance to be one, so an untyped schema whose object form
  cannot satisfy it was refused although a scalar satisfied it. The
  untyped fallback added last release for strings is a shared helper now,
  and the string and object branches both use it. A *declared* type keeps
  its contradiction. Separately, the enum-selection loop — which picks
  which permitted value to return — now uses the combinator-aware
  membership check, as every other membership question in the module
  already did.
- **A string is the default, not the requirement.** `minLength` and
  `maxLength` constrain strings and nothing else, so an untyped schema
  whose length bounds contradict is satisfiable by any non-string — and
  the clamped one-character string it returned was a value the schema
  rejects. A non-string is now tried, against the whole schema, only
  where the string default has already failed.
- **An equal enum reached through a merge is not indexed twice.** The
  index is keyed by list identity, and two defensive copies — one in
  `_allowed_values`, one in `_intersect` — meant every schema derived by
  a merge carried an equal but different list, missed the cache, and was
  charged the whole enum again. A 100,000-value enum was indexed 97
  times, exhausting the value allowance and refusing a schema well inside
  the admission limit. Both copies defended against a mutation no caller
  performs; they are gone, and the invariant they implied — nothing here
  mutates a list it did not build — is now stated and tested instead.
- **The injection audit now requires an anchor to be unique.** A case
  whose anchor matched two sites was applied to the first and still
  reported "caught" — proving something, but not necessarily the thing it
  names. An audit that cannot say which line it changed is not evidence
  about either line.
- **A speculative probe cannot bankrupt the search that follows it.** A
  sibling-seed merge ran against the live shared budget and caught its
  own failure, leaving that budget negative and ending the generator
  quietly — so every later source found nothing left and the fallback
  answered with a value the schema rejects.
- **A sibling combinator supplies candidates as well as vetoing them**,
  and supplying them never costs an arm that could not take them: where
  the arm has a combinator of its own and the two cannot be combined, it
  is built alone and the sibling goes on judging the result.
  Teaching the search to reject values a sibling forbids left the
  schemas where that sibling is the only source of a valid value — the
  arms offered nothing acceptable and the fallback answered with
  something the schema rejects. The sibling now takes part in building
  the candidates it judges.
- **The synthesiser's test coverage is verified by injection.**
  `scripts/synth_keyword_audit.sh` injects one plausible defect per
  keyword the synthesiser claims to honour, and per structural property
  no keyword names, and requires the suite to fail for each. A keyword
  appearing in a test case and being checked by one are different
  properties — and so are an audit passing and an audit looking: two
  anchors went stale when a later fix moved their call sites, and
  because each case was written `inject … && check`, the skipped checks
  left the run reporting success. A missing anchor is now a failure.
  So is a check that never reached a verdict: any nonzero pytest exit
  used to read as a caught mutation, so a missing dependency or a
  collection error reported twenty catches and exit 0 without running a
  test. A catch now requires pytest to have run and failed — and the
  suite must be green unmutated before any case runs at all, since
  against a red suite every injection is "caught" by something else.
- **Generated schemas as well as written ones.** Beside the hand-written
  corpus, 400 satisfiable-by-construction schemas are generated from a
  fixed seed range and required to be answered with a document their own
  schema accepts. Replaying the batch's nine synthesiser defects against
  the generator alone caught three at first; the six misses were gaps in
  the generator, not the check, and closing them brought it to nine.
- **Everything the stub synthesises is validated against its schema in
  CI.** Five rounds of review findings shared one sentence — the
  document must satisfy the schema it came from — so a corpus covering
  every keyword the synthesiser claims to honour is checked with a real
  JSON Schema validator, and the build fails when a claimed keyword has
  no case exercising it.
- **Enum intersection uses JSON Schema equality, not Python's.**
  `true` and `1` are one value to Python and two to JSON Schema, so
  `allOf` of `enum: [true]` and `enum: [1]` merged to `true` and
  answered with it for a schema nothing satisfies. The comparison is
  type-sensitive and recursive, and `1` and `1.0` stay equal.
- **An enum candidate must clear the schema's other constraints.**
  `{"enum": [1, 2], "minimum": 2}` answered `1`; the first *permitted*
  value is now also the first *valid* one, and a schema whose enum and
  bounds share nothing is refused. Keywords the synthesiser cannot
  evaluate eliminate no candidate.
- **Composed schemas intersect their value constraints.** Two `allOf`
  branches allowing `["a","b"]` and `["b"]` synthesised `"a"`, violating
  the second; `const` counts as a one-element enum, and branches sharing
  no value are refused by path instead of answered.
- **Keyless mode refuses audio rather than answering without it.** A
  request whose `modalities` ask for audio gets `message.audio` from a
  real provider; the stub cannot synthesise audio, and bytes shaped like
  a wav that decode to nothing would fail in the caller's decoder rather
  than at the gateway, so it refuses by name. `logprobs` and
  `top_logprobs`, which a fixture *can* stand in for honestly, are
  synthesised instead of returned null.
- **The keyless deadline covers work already under way.** An async
  timeout cannot interrupt synchronous code, so a budget that ran out
  while a fixture was being synthesised still produced an answer; the
  elapsed time is measured across that work now and an overrun refused.
- **Composed schemas keep every constraint.** Two `allOf` branches
  constraining the same property kept only the last, and fractional
  numeric bounds after the first were dropped entirely.
- **Keyless mode observes the invocation deadline.** A spent invocation
  was refused against a real provider and answered by the stub, so a
  deadline-sensitive flow could pass the demo and CI and fail once
  credentials were enabled. All three stub paths now refuse identically.
- **`allOf` schemas are satisfied, not sampled.** The stub treated
  `allOf` like `anyOf` and returned an instance of the first subschema
  only, so a schema composing two object fragments produced an object
  missing half its required keys.
- **The agent template works again.** Removing its obsolete step-config
  methods took the `analyze` and `investigate` handlers with them, so an
  agent copied from the documented scaffold failed on its first phase.
  Both are back, every bundled agent's declared phases are now checked
  against what it can run, and `run_phase` reports a phase with no
  implementation by name instead of raising a bare `NotImplementedError`.
- **Keyless mode honours `minLength`.** A structured-output schema asking
  for a long string got the short fixture marker and was rejected by
  strict consumers — the one thing keyless mode exists to avoid.
- **A run token grants what it was minted with.** Adding a capability to
  an agent's manifest used to reach backwards into tokens issued before
  it, so an invocation that began with no model access could start
  making model calls. Removals still take effect immediately.
- **Every walker enforces the walk's depth bound.** Seven of the ten
  recursive walkers never compared depth with `MAX_DEPTH`, so a deeply
  nested request was accepted well past the limit and a very deep one
  raised `RecursionError` inside the redactor rather than being refused.
- **Keyless mode will not synthesise a dataset.** A `response_format`
  schema with a huge `minItems` became that many values on the event
  loop; a total node budget now refuses such a schema instead.
- **A provider key in an agent-key variable is refused.**
  `LIBRERUN_AGENT_KEY_<ID>` becomes the container's `OPENAI_API_KEY`, so
  the `lr_agent_` format exists to make pasting a provider key there
  fail loudly — and nothing checked it, so the gateway honoured one as
  an agent credential while handing the container a spendable provider
  key. Both the environment and a presented bearer are checked now, and
  the refusal never echoes the value.
- **Keyless mode refuses what a real provider refuses.** The request
  allowlist ran only on the credentialled path, so `LIBRERUN_STUB_LLM`
  accepted routing and credential fields that a live call rejects — an
  agent built against the demo broke on its first real call. Validation
  now runs before the provider is chosen, on all three egress paths.
- **A model call no longer holds a database transaction.** The request's
  session stayed open across the provider call and the whole of a
  stream, so an agent's concurrent calls serialized behind a row lock on
  its own key and slow calls tied up the connection pool. Routes finish
  with the database before they call a model.
- **An expired run token cannot buy a model call.** The gateway read
  the token record and its expiry in two round trips, so a key that
  expired in between came back as a record with no deadline — and no
  deadline meant no bound at all. Both are read together now, and a
  token whose key has no life left is refused. The backend's MCP router
  had the same shape and is fixed with it.
- **The refusal table is checked against the code.** `§10` of the
  gateway authoring page was missing four codes and promising none that
  do not exist only by luck. The suite now fails if the two disagree in
  either direction.
- **A spent invocation is refused, not given another second.** The
  deadline scope floored the remaining budget at one second, so a fast
  call could still be launched, billed and completed after the deadline
  it was meant to enforce. An exhausted budget is now refused before the
  provider is called; a small budget is passed through as it is.
- **The invocation's deadline is absolute, and the gateway enforces it.**
  The remaining budget was read at authentication and used at the
  provider call — with body parsing, step resolution and the synchronous
  redaction walk (~2s on a large request) in between, so the provider
  got an allowance that was already spent. The principal now carries an
  absolute deadline and every call site recomputes. And because LiteLLM's
  `timeout` covers the request rather than iterating a stream, the
  gateway wraps the whole operation — stream iteration included — in its
  own wall-clock scope, refusing with `504 invocation_deadline`.
- **A provider call never outlives its invocation.** The gateway gave
  LiteLLM only the step timeout, so a call admitted with seconds of
  invocation left — or for a step declaring no timeout — ran to the
  step's limit or until the provider stopped. Nothing upstream could
  prevent it: the backend's transport ceiling closes a client socket and
  the runner's deadline is in another process. The gateway now bounds the
  provider timeout by the run token's remaining lifetime, on the chat,
  streaming and embeddings paths alike.
- **The gateway redacts with the operator's settings, not its defaults.**
  `PII_PHONE_REGION` (and `LOG_REDACT_PII`) reached the backend but not
  the gateway, which runs the same walker — so a region-specific phone
  number the backend refuses could pass the outbound walk and reach a
  provider. Both are passed now, and the guard that watches for this is
  derived from the gateway's imports rather than a hand-kept list.
- **A tool call inherits what is left of its invocation.** The
  capability façade's budget clock starts when the façade is built, and
  the MCP router builds one per tool call — so a `kb_search` late in a
  phase was handed the whole phase again. Because the MCP handler is a
  separate HTTP task, cancelling the runner would not have cancelled an
  embedding already admitted there. The remaining budget now comes from
  the run token's Redis TTL, which already encodes the absolute deadline.
- **`stub_mode()` asks the gateway.** It read the backend's
  `LIBRERUN_STUB_LLM`, which this batch moved to the gateway, so it
  answered `False` in every standard keyless deployment — and it is
  documented as a statement of fact an agent may print. It is now
  asynchronous and asks `/healthz`, answering `False` when the gateway
  cannot be reached rather than claiming fixtures on no evidence.
- **The SDK no longer clamps a call to the default ceiling.**
  `LIBRERUN_MAX_PHASE_SECONDS` is configurable and step deadlines have no
  maximum, so a container disconnected at 3600s on a deployment that
  allowed more. The constant applies only when an invocation supplies no
  deadline at all.
- **An upgrade does not pin an agent's defaults.** Migration 014 seeds a
  tenant override only where the persisted overlay differs from the
  packaged defaults — but this batch moved those defaults from
  `config.json` into the manifest, emptying the comparison base, so on a
  real upgraded installation every value looked changed. The base is now
  the packaged `pipeline` block for a tree still in the old shape, and
  the manifest's `llm.steps[]` otherwise.
- **`SPAN_ONLY` and `EVENT_ONLY` mean what they say.**
  `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` has four values
  and content was written to both destinations for any of them but
  `NO_CONTENT`, so an operator who picked one destination still got the
  other.
- **An audio completion is recorded as what it is.** `modalities` and
  `audio` are forwarded on purpose, and such a reply puts its answer in
  `message.audio` with `content` null — recorded as an empty choice. The
  span now keeps the walked transcript and the size of the audio
  payload, never the payload, streamed and not.
- **The Google provider option actually reaches Google.** The admin
  configuration surface offers `openai`, `anthropic` and `google`, but
  LiteLLM routes Google AI Studio as `gemini/<model>` and rejects
  `google/<model>`, so every step configured with the advertised Google
  option failed provider resolution without ever reaching a model. The
  public name is translated at the one point it becomes a route, and the
  step still reports the word the admin chose.
- **A safety refusal is treated as the prose it is.** OpenAI puts a
  refusal in `message.refusal` and usually leaves `content` null.
  Outbound it was walked as structure, so a refusal naming a customer
  went to the provider verbatim while the same name in `content` was
  redacted — and a refusal containing an email refused the whole request
  instead. Inbound it was ignored, so a refusal reply was recorded on the
  span as an empty choice. It is now redacted like content and recorded
  on the prompt side, the completion side and the streamed assembler.
- **A model that rejects structured output degrades instead of failing
  the run.** Each of the three provider integrations this batch replaced
  retried without `response_format` and let the parser and normalizers
  work; the unified path propagated the provider's 400. The fallback is
  back, narrowly: one retry, only for a provider refusal that names the
  feature on a call that sent it.
- **Schema-drift rows name the provider that answered.** An
  OpenAI-shaped reply names no provider, so the manifest's packaged
  default stood in — wrong for exactly the tenants who overrode it. The
  gateway resolves the step, so it now returns the resolved provider,
  model and step id in the `librerun` envelope.
- **An embeddings span no longer claims the model said nothing.** The
  completion walker reads `choices`; an embeddings reply has `data`, so
  every embeddings span carried `gen_ai.output.messages: []` — evidence
  that was wrong rather than missing. `record_response` is operation-
  aware now: an embeddings span keeps the shape of what came back
  (`librerun.embeddings.count`, `.dimensions` — counts, not content),
  and an operation nothing knows how to describe gets silence instead of
  a false claim.
- **A call is bounded by the timeout you configured, not by the
  client's.** Three clocks bound a model call — the phase deadline, the
  step's `timeout_seconds` (enforced by the gateway), and the backend's
  HTTP ceiling — and the third was a flat 120s while the bundled agent
  ships a 180s step. A call the admin had allowed was cut off by the
  client, billed by the provider, reported as `gateway_unreachable` — a
  healthy gateway named as down — and, at status 0, retried twice more.
  The ceiling is derived from the invocation's remaining budget now, so
  the step timeout is the smaller number by construction; connecting
  keeps a short bound of its own; and a gateway that answers late is
  `504 gateway_timeout` rather than an absence. The same two fixes are
  in the SDK, where `Invocation.seconds_left()` already existed and the
  LLM client was not asking it.
- **A container agent's LLM steps are configurable, and its card says
  so.** The admin index computed `has_config` from `config_meta()` even
  after the route learned to serve manifest-declared steps, so the card
  read "No admin config" and linked nowhere. One predicate now serves
  the page and links to it.
- **`config_get` answers in the MCP content envelope** like every other
  tool. Returned raw, the SDK's client read `result.content`, found
  none, and reported no steps — silently, an empty list being a legal
  answer.
- **A legacy `function_call` is recorded.** The gateway forwards
  `functions`/`function_call` on purpose, and such a response carries
  its whole answer there with `content` null, so the span recorded an
  empty choice for it — streamed and not.
- **A container agent's LLM steps are configurable.** The config page
  was gated on `config_meta()`, which a container has no way to
  implement, so the reference container declared a step editable nowhere
  while `step_not_configured` pointed at that page. Steps are the
  manifest's declaration and the tenant's rows; settings stay the
  agent's.
- **One OpenAI endpoint, for chat and embeddings alike.** `OPENAI_BASE_URL`
  was applied to chat and not to embeddings, and compose never passed it
  to the gateway at all — so an operator pointing the deployment at a
  compatible service had the setting ignored entirely, and had it
  reached the gateway, their knowledge-search query text would have gone
  to OpenAI's own endpoint while the chat went where they asked.
- **A streamed answer is recorded as the model gave it.** The span's
  aggregate kept only `delta.content` and one finish reason, so a
  tool-calling stream recorded an empty completion and `n > 1` collapsed
  into one fabricated choice.
- **A streaming call is refused before it is sent.** The trace check and
  the provider-setup failure both sit ahead of the response now: a
  foreign `traceparent` no longer reaches the provider before its 403,
  and a refused setup leaves an error span rather than no sign that a
  call was attempted.
- **`LIBRERUN_KB_EMBED_MODEL` reaches both services.** The gateway
  enforces it; the backend reports its default on the settings page, and
  was showing the built-in model while the gateway routed the
  environment's.
- **An environment key takeover honours its own `_PREVIOUS`.** Over an
  admin-issued key the declared predecessor was installed and then
  deleted by the takeover that followed it, leaving the admin key in
  that slot instead.
- **The upgrade seeds only what an installation actually changed.**
  Migration 014 wrote every packaged value as a tenant override, which
  froze the agent's defaults for installations that had never edited
  anything.
- **Model configuration is data** (L25, D13): `llm.steps[]` in the
  manifest with the defaults an agent ships, `agent_step_configs` keyed
  by **tenant** for the admin's overrides — the shared file meant a
  second tenant's edit overwrote the first — and resolution at request
  time, so changing a model in the admin UI changes the next call with
  nothing restarted. The model that answered lands on the run's progress
  entry, so the run page shows it.
- **Outbound redaction, total by construction.** Every string the model
  will read is rewritable (redacted) or unrewritable (checked, and the
  request refused); there is no third class forwarded unexamined, and
  the walk's default for an unrecognised path is the strict one. Media
  parts and token-id embeddings input are refused rather than forwarded
  while the switch is on. A totality test walks a maximal request and
  fails on any position that is neither redacted nor refused — with a
  negative test that disables strict mode and requires it to go red.
- **One LLM span, with the cost on it**: `gen_ai.request.model`, token
  counts and `librerun.cost_usd`, inside the run's tree. Content goes
  through the walker whatever `llm.redact_outbound` says — that switch
  governs what the model sees, never what telemetry keeps — and the
  backend now installs no LLM instrumentor at all, so nothing records a
  provider's reply verbatim beside it (gap H8). A `traceparent` the
  propagator cannot use no longer makes that span a root of its own: an
  unusable header falls back to the invocation's phase span, exactly as
  an absent one does, while one that still names another trace is
  refused as before.
- **The gateway's log lines are walked** (gap H10 in that process). The
  walk sits on `logging.Logger.callHandlers` — the one point every
  record passes exactly once, whatever logger emitted it — rather than
  on a filter, which only ever runs for the logger it is attached to;
  and `structlog` is configured onto the stdlib factory, without which
  the gateway's own lines went straight to stdout and were never
  records at all. Positional args, tracebacks and stacks are rendered
  before the walk in both processes now, from one implementation:
  `log.warning("hello %s", name)` leaves the name in `record.args`,
  which no walk of a record's strings touches and a formatter
  interpolates afterwards.
- **A step override row records a divergence.** The admin page shows the
  effective step — the agent's defaults and the tenant's choices in the
  same inputs — so it posts the whole row; the server stores a value
  equal to the manifest's default as no override at all, and deletes a
  row left carrying nothing. Without that, one click of Save pinned
  every default for that tenant and the agent's next release could never
  reach them. Clearing an input now posts `null` and clears the
  override, which it previously could not.
- **What reaches the provider library is an allowlist.** The gateway
  forwarded the request body minus a few keys into a call that also
  accepts `api_base`, `api_key`, `extra_headers` and the vertex and
  bedrock routing — so an agent could name its own endpoint and have the
  gateway post the tenant's content and its real provider key to it.
  A parameter is model input, or the step's, or the request is refused
  naming it. The output budget is the step's under both its spellings:
  `max_completion_tokens` had been the caller's while the admin's
  `max_tokens` was dropped for the models that use the other name.
- **A provider's refusal comes back as a refusal**, with the status the
  provider chose, instead of a 500 the chassis retried and then reported
  as an outage. The gateway's own keys are removed from the message.
- **A step whose manifest leaves the model to the admin can be
  configured.** Such a row rendered greyed out and labelled "No LLM"
  with its inputs disabled — `llm.steps[]` holds only LLM steps, so no
  provider means "the admin chooses", and that agent could not be set up
  anywhere while every call returned `step_not_configured` pointing at
  that page.
- **`user` is replaced whatever the redaction switch says.** It is not
  model input: it is the handle the provider files requests under and
  keeps, so an end user's address there registers that person with the
  provider. An agent may opt itself out of redaction; it may not opt
  someone else into that.
- **Keyless mode is the gateway's** (D4): `LIBRERUN_STUB_LLM=true` makes
  `stub` the provider for every step, answering from a named script, the
  caller's own fixture, or an instance synthesised from the request's
  own JSON Schema — so a structured-output agent runs keyless with no
  agent content living in the platform. A stub call is costed against
  the model it stands in for.
- **The demo banner reaches the console immediately.** S4 replaced
  `sys.stderr` with a writer that turns each line into a walked, queued
  log record; the first walk loads spaCy, so the "not for production"
  banner could surface seconds after the API was already serving. It now
  goes straight to the descriptor taken before that capture. It is the
  one message that skips the walk, and it carries no value by
  construction — the lines are literals, and a test fails the moment one
  is built by interpolation.
- **The model that answered a step** is written to
  `run:{id}:step_models` and joined into `GET /runs/{id}/progress`, so
  the run page shows it (D13). On the trace, the resolved provider and
  model are stamped as chassis-written, and so is the span's name, which
  the GenAI convention builds from the model: unstamped, the export's PII
  walk reads a model name as a person's and the one fact D13 is about
  reaches the viewer redacted.
- **Per-agent keys** (D10): `LIBRERUN_AGENT_KEY_<ID>` provisioned into
  `.env` before `up`, derived by `compose.sh` into `agent-keys.env` and
  passed to the gateway alone. The value is never stored — only its
  sha256 and the eight characters after `lr_agent_`. A key names an
  agent and not a tenant, so it authenticates `GET /v1/models` alone and
  every model call needs the run token beside it, in every mode.
  Rotation in `.env` with a `_PREVIOUS` line, or from the platform-admin
  API with a grace window; two agents sharing a value stop `compose.sh`
  by name, before `up`.
- **The knowledge base's query embedding moved** onto the gateway under
  the platform-reserved `kb_embed` step, routed by the `kb.embed_model`
  setting and bounded to exactly what `kb_search` already lets the `kb`
  grant cause. No provider URL is left in the capabilities module.
- **Migration `014_agent_gateway_tables`**: `agent_manifests` (snapshots
  written at discovery, stamped `absent_at` when an agent disappears and
  never deleted), `agent_step_configs` and `agent_keys`. The upgrade
  seeds every existing tenant's step overrides from the legacy
  per-agent file, so nothing visible changes for anyone.
- `docs/authoring/LLM_Gateway.md`; `ctx.llm.complete` and
  `ctx.config.steps()` on the SDK; the MCP `config_get` tool.

### S4 — Run Contract finished: one trace tree, deadlines, the Python SDK
- **One trace per run, across the approval gate.** The submission request
  opens a root `run` span, and every phase — before and after approval,
  in whatever process — restores it as its remote parent, so a gated run
  is one tree and its trace id never changes. The W3C pair is persisted
  on the row (`root_traceparent`, `root_tracestate`; migration
  `013_run_root_trace` retires the `phase1_*` pointers). An upstream
  `traceparent` is adopted and a vendor `tracestate` survives the gate;
  a caller's unsampled flag cannot silence a run.
- **Per-phase deadlines.** `phases[].deadline_seconds` in the manifest,
  bounded by `LIBRERUN_MAX_PHASE_SECONDS` (3600). The runner enforces it,
  the container `POST /v1/runs` body carries it, and the run token's TTL
  follows it. Parked time at a gate is never counted.
- **`librerun-agent`, the Python SDK** (`sdk/python/librerun-agent`): one
  `async def handler(ctx)` served by `serve(handler)`, with progress and
  log events, the capability clients, `ctx.pii.redact`, OTLP export
  configured from the environment and partitioned per invocation, and
  stdout/stderr capture that follows the invocation into threads and
  executor jobs. `docs/authoring/SDK.md` maps every control function to
  one surface; `docs/authoring/Container_Agents.md` is Python in ten
  minutes and the wire contract for every other language.
- **PII redaction as a service.** The `redact` MCP tool and
  `ctx.pii.redact()` behind a `pii` manifest grant — the intake pipeline
  on demand, for anything an agent fetches at runtime. Without the grant
  the tool is not listed and the call is refused.
- **Everything an agent hands the chassis is walked.** One walker over
  terminal output, `audit_log` arguments, the run-store key and value,
  `progress.step_id` and event text: strings redacted, object keys and
  numbers checked, and a flagged one refusing the write
  (`pii_in_output`, `pii_in_audit`, `pii_in_store`, `pii_in_progress`).
  Audit attribution is stamped by the chassis from the run owner and is
  no longer something an agent can pass.
- **Everything the box exports is walked**, at three attach points: the
  span and log walkers in the backend, queue-only logging that captures
  `print()`, `sys.stderr` and raw descriptor writes as records of their
  own plane, and an authenticated OTLP relay for containers. A flagged
  key or number strips a span to its identity; a totality test over the
  OTLP descriptor proves no position is missed.
- **The agents network.** Agent containers join an internal `agents`
  network and reach the chassis and nothing else — not Vector, not the
  Internet; `network.egress: true` in the manifest plus the `egress`
  network in the compose fragment is the documented opt-out. Their
  logging driver is `none`, so `docker logs` on an agent is empty by
  construction.
- **The container battery.** `python -m adapter_kit.run_contract --url …`
  drives any Run Contract v1 URL through schema-valid output, progress,
  `completed`, token binding and one trace tree, with a relay recorder
  for the container's own spans. `.github/workflows/container-battery.yml`
  builds the reference agent's image and runs it.
- The platform plane binds opaque ids only: `user_email` is refused by
  the log context and gone from the middleware.

### S3 — Zero-config demo and the delight gate
- `./scripts/demo.sh`: on a machine with Docker or Podman and nothing
  else, writes a demo `.env` (generated secret and credentials, demo
  mode, the stub LLM, the bundled agent and the LangGraph example, a
  local Jaeger), builds and starts the stack, and prints the URL, the
  credentials and the trace viewer's address.
- Demo mode (`LIBRERUN_DEMO=true`): the only mode that accepts the
  shipped default `APP_SECRET_KEY` — the backend refuses to start on it
  otherwise — announced by a startup banner, a banner in the UI and a

  `trace_viewer_configured` and the installed agents.
- `LIBRERUN_AGENTS_PATH` takes several directories separated by `:`;
  the backend image carries the LangGraph adapter so the example runs
  beside the bundled agent.
- "View trace" links on the run pages when a viewer is configured.
- The backend service carries a compose healthcheck: `compose ps` shows
  `(healthy)` once the API answers.
- `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` defaults to
  `NO_CONTENT` in `.env.example`; the demo turns it on.
- The delight gate: `scripts/delight_gate.md` (the timed walk) and

### S2 — The platform stops saying VITA
- Chassis defaults are LibreRun's: database and role `librerun`, index
  `librerun-kb`, image user `librerun`, volumes `librerun-*` (all
  env-parameterised so an existing deployment keeps its data; see
  `docs/Install.md`, "Upgrading an existing deployment").
- Admin configuration edits persist across container recreation on the
  new `librerun-state` volume (`LIBRERUN_STATE_DIR`).
- Every run has a title (`ui.list.title_path` in the agent manifest); the
  run list shows and searches it. `GET /runs/{id}/approval` serves the
  approval gate for every agent; `/refined-statement` is deprecated.
- Retrieval documents are stamped by the step through `kb.stamp`.
- The schema file is `backend/db/schema.sql`; the `chassis-purity` CI job
  keeps agent names out of the chassis.
