# LibreRun 1.1.0-beta.1

LibreRun is an educational software environment for teaching the
design, development and operation of AI agents using multiple
agent-development frameworks. Its scope is agent conception and
planning, framework selection, security, operating environments,
observability, evaluation and optimization; its architecture uses
Docker Compose or Podman Compose to orchestrate its containers within a
Linux virtual machine, and it runs on Linux only. At its centre is a
self-hosted chassis for AI agents, built for educational purposes: a
complete, working platform to learn from — how an agent is conceived,
what a framework gives it and what the platform gives instead, how a
run is observed, where the security boundaries lie, and what an agent
needs from the environment it runs in. The chassis is real, not a mock:
an intake wizard, a human approval gate, PII redaction before anything
is stored, per-step model configuration, reports, and one trace per
run. You bring the agent; LibreRun brings everything around it.

That description commits the tree to four things:

- **Linux only.** macOS and Windows are not supported, not through
  Docker Desktop and not through WSL2.
- **The orchestration is named.** Docker Compose or Podman Compose runs
  the stack over `compose.yaml` and `agents.compose.yaml`, driven by
  `compose.sh`.
- **Agent conception and planning are taught in person.** The tree
  carries the anatomy of an agent
  ([`Agents_Design.md`](../authoring/Agents_Design.md)).
- **Evaluation and optimization are taught with the chassis's own
  instruments** — the gateway, which is the LLM router every model call
  passes through, the edge proxy, the cache, and the tracing and
  observability tools, all designed to teach evaluation — and the pages
  that teach them are not written yet, as the list below says.

**1.1.0-beta.1 is LibreRun's first public release, and it is a beta.**
1.0 was certified on 2026-09-22 and never published; this beta is 1.0
with everything planned for the public beta added, and it is released
as source only. It makes the same three promises, keeps them, and says
plainly what it does not do yet.

## The three promises

### 1. Five minutes to a gated, traced run — no keys, no config

```bash
git clone https://github.com/JeremiahJRRoss/librerun.git && cd librerun
./scripts/demo.sh
```

The script builds the stack from source: every first-party image is
built from the checkout and never pulled, and the upstream images it
runs are pulled by tag and digest. There is no published image to start
from and no `--pull`. On a fresh CI runner it took 4 min 0 s on this
candidate; on an ordinary laptop, well within fifteen minutes.
Sign in with the credentials the script prints. Then take **+ New Run**
→ an agent card → **Try a sample** → submit, watch the steps,
**Approve** at the gate, read the report and press **View trace**. Five
agents ship in the box and all of them run keyless, through the
gateway's built-in stub provider:

- **VITA**, the demo agent that investigates cross-vendor integration
  failures;
- an **echo** reference agent;
- examples in **LangGraph**, **LlamaIndex** and the **Vercel AI SDK**.

A keyless run is not a mock. Every call still passes through
authentication, PII redaction, model resolution and the trace — only the
answer comes from a fixture.

### 2. Your agent in an hour, and the platform snaps in

```bash
pipx install "git+https://github.com/JeremiahJRRoss/librerun#subdirectory=cli"
librerun init my-agent --template langgraph
librerun up
librerun run --agent my-agent --wait
librerun battery --agent my-agent
```

`init` scaffolds the agent; `--template container-python` or
`container-ts` takes the container path instead. `up` rebuilds the stack
with the agent on the new-run page, `run --wait` follows its sample to
the end, and `battery` is the conformance battery: green means done.
There are two paths, and CI proves both on every change: a LangGraph
graph in-process through `librerun-langgraph`, or a container in any
language speaking the [Run Contract](../authoring/Run_Contract_v1.md),
with the `librerun-agent` Python SDK or the single-file TypeScript
reference server as its starting point. Either way the agent gets the
platform's services without building them, and every model call goes
through the **LibreRun gateway**, so an agent never holds a provider
key. [`docs/authoring/Quickstart.md`](../authoring/Quickstart.md) is the
hour path end to end.

### 3. Every run is one trace, in the tool you already use

Jaeger is in the box. Each run is one tree rooted at the run, across
the approval gate: intake, every phase, every model call with its model,
tokens and cost, and the agent's own spans when it emits them. Every run
has an audit log, and PII is redacted before anything is stored. Tested
overlays send the same logs and traces to **Datadog**, **Elastic** or
**Splunk** ([`docs/platform/Observability.md`](../platform/Observability.md)).

## What the beta adds

Everything 1.0 was certified with, and:

- **The licence: AGPL-3.0-only**, with four Apache-2.0 directories an
  agent builds on, and a running LibreRun that says which licence it is
  under and where the source of its version is (`/api/v1/meta`, and a
  Source link on the login page and in the navigation bar).
- **Settings and secrets as data, set in the admin UI.** An agent declares
  its settings in its manifest and each tenant's admin sets this tenant's
  values; a secret setting — the Microsoft sign-in secret, the knowledge
  base's key — is stored encrypted under the backend's store key; a tool
  secret an agent declares is set per tenant, with a default for every
  tenant, and read by a run without ever being shown; a provider key is
  pasted on Application Settings, sealed in the browser to the gateway's
  public key, and adopted by the gateway with nothing restarted — the
  backend stores what it cannot open.
- **The admin surface, complete.** A read-only Deployment panel; each
  agent's Keys tab, to issue, rotate and revoke the key it presents to the
  gateway; a scope chip on every editable field; and each platform-only
  page explained to a tenant admin rather than refused with an error.
- **HTTPS at the edge**, opt-in: the `tls` profile terminates TLS on one
  port with a certificate from its own CA, from ACME, or of your own, and
  sends HSTS and a Content-Security-Policy; the plain ports bind to
  loopback by default. Admin → Application Settings → **Certificates**
  says what the edge serves and what it needs next, and loads a CA, a
  certificate, or ACME, with no shell and no restart. The CA's private key
  never leaves the edge's volume.
- **Source only.** Every first-party image is built from the checkout and
  never pulled; nothing is published but the tree.
- **Dependencies pinned by identity:** every image by tag and digest, the
  gateway installed from a hashed lock, LiteLLM exact and used as a
  library alone, and Valkey 8 as the cache server.
- **The release machinery:** one `VERSION`, release notes from
  `CHANGELOG.md`, and a first public commit that carries the tested tree
  exactly.

[`CHANGELOG.md`](../../CHANGELOG.md), under 1.1.0-beta.1, has it batch by
batch.

## Source only

A release is the repository at its tag, with the notes and the source
archives GitHub makes for it. No prebuilt image, no PyPI or npm package
and no air-gapped bundle exists. Whoever runs LibreRun builds it
locally, from the upstreams [`THIRD_PARTY.md`](../../THIRD_PARTY.md) and
the [distribution surface matrix](Distribution_Surface_Matrix.md) name:
a build fetches from the origins the matrix's fetch table names —
Docker Hub, PyPI, npm, GitHub (the spaCy model) and `deb.debian.org` —
and a build without that network fails rather than builds something
else. What a build fetches says nothing about what a running stack
reaches: those flows are in [`Security.md`](../platform/Security.md),
under "Every flow that leaves the box". The CLI and the SDK install from
the tree, never from a package index.

## What the beta does not do yet

These are the edges of what the beta claims, and none of them is a bug.

**Interaction (v1.1, October 2026)**
- No mid-run human input inside a phase: gates sit *between* the phases
  an agent declares.
- No reject-with-note at the gate. You approve, or edit and re-run.
- No artifact store, so an agent's intermediate drafts cannot be
  downloaded.
- No automatic resume of a phase the backend was restarted under. The
  run is marked `error` with the reason at the next boot.

**Authoring (v1.1–v1.2)**
- No TypeScript SDK. The Vercel example is a reference server, not a
  package.
- No in-process adapters beyond LangGraph; everything else is a
  container.
- No gRPC transport, deliberately. HTTP, server-sent events and MCP are
  the control plane; a gRPC binding is considered only if someone needs
  the transport rather than the functions.

**Evaluation and cost (v1.2, November 2026)**
- No evaluation beyond scenarios that prefill and submit — no `expect`
  blocks, no scored runs.
- No measured answer-quality baseline for the VITA demo agent. A keyless
  run proves the wiring, not the judgement.
- No per-run cost panel in the UI. The cost is on the trace.
- No smart cost-versus-quality routing between models.
- No page yet teaches evaluation or optimization. The instruments are in
  the tree — the gateway, the edge proxy, the cache, the trace — and the
  lessons that use them are not written.

**UX (v1.2)**
- No live event stream. The run page polls every 2 s while a run is
  going, and stops when it ends.

**Deployment**
- TLS only at the edge, and only when you turn it on: the opt-in `tls`
  profile serves the UI and the API over HTTPS on one port, while the
  plain ports (3000 and 8000) stay on `127.0.0.1`, their default, which
  `compose.sh` enforces — on Docker the binding, not a host firewall,
  keeps a port off the network
  ([`Install.md`](../platform/Install.md#https-at-the-edge)). An `.env`
  copied from 1.0's example keeps both ports on every interface until its
  two lines are edited.
- Behind the edge, LibreRun's own services — Postgres, the cache, the
  gateway, telemetry — still talk plain HTTP on the compose network.
  TLS between them is on the roadmap, v1.2 and later.

## What a beta means

A beta exists to be tested, not to run in production, and the next one
may change anything in it.

- **Back up before each upgrade.**
  [`Install.md`](../platform/Install.md) §10, "Backup and restore", says
  what a backup holds and the order a restore takes.
- **Migrations are supplied between betas**, and each one's downgrade
  undoes only what it created: a table it made goes, with what is in it.
- **The cache volume is replaced at this beta.** Valkey 8 cannot read the
  snapshot Redis 7.4 left in `librerun-redis-data`, so the upgrade removes
  that volume and Valkey starts on a fresh one under the same name;
  nothing in it needs keeping.
- **The demo agent's settings overlay is dropped.** Its three settings are
  per tenant now, each at its default until a tenant's admin sets it.
- **1.0's compatibility aliases and redirect stubs stay through the beta**,
  and go at 1.1.0.

[`Install.md`](../platform/Install.md) §10, "Upgrading to 1.1.0-beta.1",
is the upgrade from 1.0 as one ordered sequence.

## Roadmap

### v1.1 — "Interactive agents" (October 2026)

The rest of v1.1 follows the beta, and 1.1.0 removes what 1.0 deprecated.

| Item | Acceptance |
|---|---|
| Run Contract v1.1: mid-run input as a segment boundary, resumed by a new invocation, actor identity, an input panel | the LangGraph example pauses inside a graph and resumes from the UI |
| Reject with a note; gate history; rerun from rejected | VITA's gate can be rejected with a reason that reaches the agent |
| Artifact store capability | an agent's drafts are on the run page |
| Durable resume of a phase the backend was restarted under | a run interrupted by a restart finishes `complete`, still one trace |
| TypeScript SDK `@librerun/agent`, in the tree and installed from it (nothing is published); the Vercel example moves onto it | the container battery is green from TypeScript, with one trace tree |
| Anthropic `messages` ingress on the gateway | the Claude Agent SDK example runs keyless through the gateway |
| The Arcade support-diagnosis agent runs on LibreRun from its own repository | its checklist, run live |
| File slots; every 1.0 deprecated alias and redirect stub removed | the aliases in `CHANGELOG.md`'s 1.0 **Deprecated** section are gone |
| Install extras (`pii`, `pdf`, `kb`) with explicit not-installed states | a core-only install boots and refuses unredacted intake |
| A documentation site, published on tag | it builds strict in CI |

### v1.2 — "Evaluate and watch" (November 2026)

| Item | Acceptance |
|---|---|
| Scenario `expect` blocks and scripted inputs; eval runs with comparison; run and feedback export | `librerun eval` exits non-zero on a miss |
| Server-sent events from Valkey streams; run views chosen by the manifest (pipeline, milestones, chat) | no polling; a chat-shaped agent renders as chat |
| An action ledger with cost attribution, and an Actions panel | a keyless run shows its tool and LLM actions with tokens and cost, and no prompt text |
| In-process adapters for LlamaIndex Workflows, CrewAI and the OpenAI Agents SDK | four adapter jobs green |
| Claude Agent SDK, ADK and Genkit container examples | each passes the container battery keyless |
| Smart routing in the gateway, on measured quality | a routed step is cheaper than its pinned baseline at an equal eval pass rate |
| Gateway budgets and rate limits per tenant and per agent | a run over budget stops with a clear error |
| Outbound redaction of media: image text, audio transcripts, document text | an image carrying an address reaches the provider with the address masked |
| The file-shaped agent configuration methods removed (after v1.1's settings-as-data) | agents configure through the manifest and the admin UI only |

**v1.2 and later, unscheduled:** TLS between LibreRun's own services
(Postgres, the cache, the gateway, telemetry), since the beta covers the
browser's side alone; KMS-native wrapping of the two store keys;
per-tenant provider keys; supply-chain pins beyond this beta's (actions
by commit, hashes for the backend's locks, the spaCy model and the
Debian packages); S3-compatible artifact backends; Kubernetes manifests;
per-node LangGraph spans; a hardened single-user local mode; more
observability vendors than the three named, through the same overlay
pattern.

## Security

PII redaction fails closed: when the detector is not ready, intake
refuses rather than storing unredacted text. Secrets are partitioned by
the process that reads them, the gateway is the only process that holds
a provider key, and a secret entered in the admin UI is never shown
again. [`docs/platform/Security.md`](../platform/Security.md) is the
model in full, with the gate behind each claim. Report a vulnerability
privately, as [`SECURITY.md`](../../SECURITY.md) says.
