# Telemetry — capped below the next major.
#
# An open upper bound is not a style question here; it is how a deployment
# broke. `anthropic>=0.39` with no ceiling let a routine image rebuild
# resolve a new major that had removed parameters the caller passed, and
# every Anthropic-backed step died before it built a request. That SDK now
# lives in services/gateway/requirements.txt (S4a, L23), but the exposure
# was never about that one package: it was about an unbounded range in an
# image that gets rebuilt. Everything below was unbounded above.
#
# `openinference-instrumentation>=0.1.40` is the same shape the anthropic
# entry had — a floor two majors below what it resolves.
#
# The opentelemetry contrib packages version as 0.NNbM / NbM, tracking the
# core 1.x line rather than each other, so their ceilings differ and are not
# a typo. Neither publishes a stable release, which is why a prerelease
# satisfies each range.
#
# Lift a ceiling deliberately, one at a time, with the backend suite green
# against the new version — never as a rider on an unrelated change.
opentelemetry-api<2
opentelemetry-sdk<2
opentelemetry-instrumentation-fastapi<1
openinference-instrumentation>=0.1.40,<1
openinference-semantic-conventions>=0.1.9,<1
pytest
pytest-asyncio
opentelemetry-exporter-otlp<2
